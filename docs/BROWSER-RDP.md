# 网页内 RDP 连接

在浏览器中连接 Windows 桌面使用 **guacd 图形服务**。平台的“原生 RDP”用于 mstsc 等原生客户端，是另一套能力。只使用网页内 RDP 时，无需安装原生 Worker，也无需开启“原生 RDP”或映射平台的 3389/13389 端口。

## 前置准备

1. 目标 Windows 已启用远程桌面，登录账号有远程桌面权限。
2. 部署使用图形组件配置，guacd 健康；平台到目标 Windows 的 RDP 端口可达，默认端口通常为 3389。
3. 创建目标 Windows 的账号凭据，并给使用者授予资产连接权限。这里填写目标系统账号，不是平台管理员账号。
4. 浏览器访问平台 HTTPS 入口并信任证书。共享盘和 MP4 导出是可选组件，不是登录桌面的同一个开关。

一键安装的完整模式包含图形组件；`--core` 不包含。源码部署需加载 `deploy/production/services.yaml`，详见 [源码部署](FRESH-INSTALL.md)。rc12 源码接入执行器后，也可在“平台配置 → 服务部署 → 图形组件”预检和启用已登记组件。

## 创建和使用示例

在资产管理中新增 RDP 资产，例如：

| 字段 | 示例 |
| --- | --- |
| 名称 | 办公电脑 |
| 协议 | RDP |
| 目标地址 | `192.168.1.20` |
| 目标端口 | `3389` |
| 凭据 | 该 Windows 上有远程桌面权限的账户；域按实际环境填写 |

保存后分配资产权限，使用者从“我的资产”打开浏览器连接。目标地址必须能从平台实际连接链路到达；不能将客户端电脑上的 `localhost` 当作远程 Windows 地址。

## 服务与端口

| 链路 | 用途 | 宿主端口 |
| --- | --- | --- |
| 浏览器 → 平台 HTTPS | 页面、连接及会话数据 | 平台配置的 HTTPS 端口 |
| 后端 → guacd:4822 | 图形协议转换 | 仅容器内部网络，无需公开 4822 |
| 平台图形链路 → Windows:3389 | 目标远程桌面 | 是目标 Windows 的端口，不是平台容器映射 |
| 后端 → mp4-renderer:8090 | 可选录屏导出 | 仅内部网络，无需公开 8090 |

## 排错

- **“当前节点为 Linux”**：说明后端容器运行于 Linux，Windows Docker Desktop 也会显示 Linux。
- **“当前节点未部署原生 RDP Worker 接入配置”**：仅针对原生客户端能力。只使用网页连接时可以忽略，不是 guacd 故障。
- **“无法连接部署执行器”**：影响自动部署操作，需检查执行器接管；不代表已有 guacd 一定不可用。见 [自动部署说明](AUTO-DEPLOYMENT.md)。
- **网页连接失败或黑屏**：检查 guacd 健康、目标地址/端口、Windows 远程桌面权限及凭据，再查看会话错误和图形日志。
- **文件共享或 MP4 不可用**：分别检查共享盘挂载和渲染器状态，不能仅依赖录屏/文件传输策略开关。

Linux 一键安装可执行：

```bash
sudo /opt/puppeteer/puppeteerctl ps
sudo /opt/puppeteer/puppeteerctl logs --tail=100 server guacd
```

共享盘涉及 FUSE、AppArmor 和数据卷；按 [共享盘说明](RDP-DRIVE-AUTO-DEPLOYMENT.md)处理，不通过删除卷或给整个容器增加 privileged 权限解决。
