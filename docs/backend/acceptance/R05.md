## 可直接前端测试

1. 打开本地 SSH 的文件管理，根目录应为 `/`；依次进入 **home → tester → R05-验收**，已有 `r05-中文验收.txt` 可供下载。不要更改 `.ssh` 等登录文件。
2. 上传另一份中文文件名文件。界面依次显示准备、浏览器上传/后端接收、目标传输与校验、完成；只有远端校验和提交成功才显示“已完成”。再下载，与源文件比较内容。
3. 选择不超过 256 KiB 的 UTF-8 文本“编辑”，保存后重新打开。若另一个操作已修改原内容，应拒绝旧版本保存。新上传遇同名文件直接拒绝，不静默覆盖。
4. 重命名测试副本，随后删除。目录只支持删除空目录，不递归删除。打开“文件审计”，查看上传、读取、下载、编辑保存、重命名、删除和取消结果，并可跳回访问记录。
5. 上传较大测试文件并在接收中点“取消传输”。应显示取消，文件列表不出现最终文件；可重新选择文件重试。超过 16 MiB 的单文件直接拒绝。
6. 结束当前 SSH 后重新勾选“只读”连接，文件列表和下载可用，上传、编辑、新建、重命名、删除不可用；服务端也会拒绝伪造写请求。
7. 关闭会话后从访问记录回放，确认终端输出仍正常。管理员可打开“录屏保留预览”，调整天数查看候选数量，无删除按钮。

## 实施口径与边界

- 只允许当前存活会话的本人访问文件，管理员不能借他人的 sessionId 操作其 SFTP。每次文件读取/写入重新校验登录、资产授权、版本、凭据、主机信任与会话状态；会话撤权/终止会关闭相关 SFTP 子通道。
- r05.2 挂载根改为远端 SFTP 服务暴露的系统根目录 `/`，固定于该会话；所有读写仍由登录用户的操作系统权限决定，服务端配置 chroot 时只能看到该隔离根；拒绝 `..`、反斜杠、NUL/换行、内部临时文件名，以及任何路径组件中的符号链接。目标端同时改名/换链接仍存在 SFTP v3 TOCTOU；严格隔离要由目标端 chroot/权限实现，平台路径检查不是绝对沙箱。
- 单文件上传/下载 16 MiB、分片 1 MiB、文本编辑 256 KiB；每用户最多 4 个待完成任务和 64 MiB 预留，全局 256 MiB，最多 4 个并发 SFTP 操作。目录最多返回 2000 项，操作最长 60 秒。配额针对平台暂存和传输，不代表限制远端主目录总磁盘用量，更不限制用户通过交互 Shell 写文件。
- 上传分片以 UUID + offset 幂等，相同分片不会增加计数；浏览器成功接收 100% 只是暂存完成。提交写入同目录独占临时文件，先设 0600，再写数据；支持时调用 fsync，关闭并回读 SHA256，重新检查目标版本和权限后重命名。文本编辑保留普通权限位，不保留 inode、ACL 或原所有者，需目标支持 posix-rename 扩展。
- 临时文件只使用本任务 UUID 名称；上传结果和取消状态持久化，终态释放 PostgreSQL 分片。取消与提交通过状态 CAS 区分，进入 committing 后取消返回冲突，不会删除正式文件。网络异常导致提交结果不确定时标 interrupted，应核对状态和目标内容，不自动重试。
- 接收任务 15 分钟到期，关闭会话后回收；单进程重启将传输/提交中任务标中断。远端遗留临时文件保留 cleanupNeeded 标记，在同一操作者、资产和根目录下一次可写授权文件列表访问时清理。服务长期无法访问目标时，不承诺已清除远端临时文件。
- 文件审计不保存文件内容。下载成功记录表示后端已读到目标字节，不能确认用户磁盘已保存成功；文件在阶段性暂存中属于数据库内容，应纳入数据库保密与备份策略。
- 录屏按 sequence/time/kind/payload 计算 SHA256，并核对事件数和总字节；关闭时尝试封段，失败不阻碍关闭，未封段及旧录屏首次回放前补校验。摘要不是外部签名；既有未封段历史只建立首次校验基线，不宣称能发现此前篡改。摘要不符返回 409 停止回放。保留预览、封段和回放均不删除录像。
- 本轮没有共享存储、目录上传、批量下载、文件 chmod UI、录屏文件导出、自动保留删除、对象存储或独立 Worker；原生 SFTP 网关也未实现。
