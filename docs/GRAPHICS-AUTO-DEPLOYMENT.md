# 浏览器 RDP / VNC 图形组件自动部署

开发分支功能（P1-1 第一项），尚未发布到正式镜像或远程服务器。

## 使用步骤

1. 使用匹配版本的一键安装或升级脚本，完成单机 Docker Compose 执行器接管。生产部署中已有的内部 guacd 服务会自动登记；无需手工增加端口或修改 Compose。
2. 管理员打开“平台配置 → 服务部署 → 图形组件”，查看部署配置、实际容器状态和连接中断提示。
3. 选择启用或停用，输入管理员密码；已开启 MFA 的账号还需新的动态口令，点击“预检并执行”。
4. 预检通过才提交任务，按“预检 → 部署 → 验证 → 完成”显示进度。刷新页面可继续追踪；应用重建期间使用既有独立进度通道。
5. 完成后可在“状态与发布 → 预检与服务”查看图形服务四维状态，并进行只读预检。

操作会重建应用和 Web 容器，现有应用连接（包括图形连接）会中断。当前采用立即中断策略，不等待会话排空。再次启用后需重新连接资产；已有账号权限、目标凭据及资产策略仍适用。

## 自动执行及边界

- guacd 只在内部 `graphics` 网络提供 `4822` 服务，不创建宿主机映射，不操作防火墙、云安全组或 DNS。
- 启用时检查接管记录、固定版本/摘要镜像、内部网络、后端中继地址、健康检查和设备配置，校验 Compose。镜像不在本机时自动拉取已登记的镜像，再创建或重建服务。
- 停用时清空应用 guacd 与中继地址，关闭共享盘入口，停止 guacd；保留镜像、服务定义、共享盘配置和数据卷。专用停用 profile 防止后续普通 `compose up` 或升级重新启动组件。
- 已登记共享盘要求宿主 `/dev/fuse` 存在且为设备；不满足时启用预检失败。图形开关保留已有配方；共享盘独立启停和权限管理已接入单独页签，见 [共享盘自动部署](RDP-DRIVE-AUTO-DEPLOYMENT.md)。
- 只接管本项目内部、无公开端口、无自定义 profiles 的 guacd 配方。外部 guacd、自定义中继、缺少定义或所有权、其他服务依赖 guacd、混用网络模式等配置会被拒绝并说明原因，不覆盖自建服务。
- 不从表单接收镜像、卷、宿主命令或端口参数。组件部署复用管理员授权、密码/MFA、审计、并发互斥、generation 校验与持久任务。

预检检查部署条件，不会拉取镜像或改变容器。镜像仓库在执行时不可达、启动健康检查失败等情况仍可能导致部署失败，失败后恢复原配置和运行状态。关闭失败或执行器中断时执行保持关闭流程；如果 Docker 不可用而无法确认停止，任务保留失败原因，不显示关闭成功。

## 状态与验证

四维状态分开显示：部署期望、最近配置应用结果、当前版本的依赖预检、实时服务探测。宿主观察 guacd 容器数量、健康及公开端口；启用时从应用侧验证 RDP 和 VNC 的 `select/args` 协议握手，停用时核验应用入口关闭、组件停止且内部地址不可连接。

握手成功证明 guacd 插件可响应，不证明某个目标资产的网络、账号、授权或桌面环境可用。旧执行器没有图形能力时，页面显示明确的不支持原因并禁止提交；实际状态无法取得时显示未知，不把配置开关当成运行证据。

## 安装与升级兼容

新安装从服务器镜像携带的接管程序登记内部组件。已接管的旧安装在升级阶段，从新镜像提取接管程序，将图形元数据补入现有 `compose-managed.json`；保留原镜像引用、共享盘模式、卷和自定义配置。已停用组件的 profile 与状态不被升级重置。升级过程不替换已有可选组件镜像，也不升级 PostgreSQL。

服务端、前端、宿主执行器及脚本需来自匹配版本。已发布的旧版本不因此自动具备此功能；正式发布前仍需完成整机安装与既有数据升级验收。

## 本地验收

- Go：内部配方限制、禁用公开端口、设备预检失败无变更、停止失败保护、回滚保留停用状态、真实容器状态解析及 RDP/VNC 握手。
- PostgreSQL 应用集成：统一状态、旧执行器兼容、组件停止证据、只读预检及原有授权/版本/取消/过期流程。
- Linux 安装、升级及接管脚本 28 项回归；实际 systemd 使用镜像内接管程序验证自动登记；前端类型检查、配置导航/HTTP 等 16 项测试和生产构建。
- 隔离 Docker 项目：启停、普通启动不重新打开、持久卷保留、执行器中断时启用回滚和停用保持关闭；使用无真实桌面与凭据的 VNC 色块夹具验证画面及连接终止。
- 浏览器 API 夹具：无端口表单、当前状态、预检失败不提交、任务进度/刷新、密码清空、旧执行器禁止执行及窄屏布局。界面夹具不替代真实组件验证。

Docker 验收命令（显式指定本地测试镜像和编译的 Linux 夹具二进制）：

```bash
python3 tests/deployd_docker_integration.py --graphics --recovery \
  --server-image puppeteer/server:p1-graphics-final \
  --vnc-fixture backend/.local/graphics-vnc-fixture
```

夹具源文件为 `backend/fixtures/vnc/main.go`；测试仅创建带唯一名称的临时项目并在结束后清理。

补充：扩大 Python 测试发现既有 Agent Skill 安装测试在 Windows CRLF 文件通过 Linux 挂载读取时未通过（要求 `---\n` 文件头）；本阶段未修改该独立安装器。图形组件相关安装与升级测试均通过。
