| 功能 | 实现及边界 |
| --- | --- |
| LDAP | LDAPS / 强制 StartTLS；显式选择目录登录；稳定 entryUUID / objectGUID 绑定，跨账号冲突拒绝；用户和提供方变更使旧会话失效；MFA 中间态沿用平台策略。 |
| LDAP 同步 | TLS 分页完整读取、1–10000 条上限，拒绝部分结果和重复身份；5 分钟、浏览器绑定的预览，每批最多 100 个账号。只导入所选稳定身份；新账号默认停用、无角色、无本地密码，管理员在用户管理审核、设置密码/权限后启用。支持默认部门；显式停用已离开完整目录的托管普通账号并撤权；不覆盖手动绑定或管理员。 |
| OIDC / 企业微信 | 提供方配置、测试、绑定/解绑、登录；企业微信使用应用 access token 和成员 UserID，CorpID+UserID 为主体；拒绝非成员、跨浏览器、回调混用、过期与重放。OAuth/OIDC 对外提供方使用 PKCE/nonce/签名验证，企业微信使用其官方应用授权协议，不伪称其提供 OIDC ID Token。 |
| 平台 OIDC 服务端 | 固定 HTTPS Issuer；discovery / JWKS、RS256 密钥轮换；严格回调地址、S256 PKCE、显式 consent；授权码一次性消费；刷新令牌轮换、重用撤销整族、缩小权限后不可自动恢复；client_credentials 仅有 service scope，不产生用户身份或管理权限。 |
| 客户端管理 | 密钥只在创建/轮换时显示；按用户或直接所属部门授权；scope 和白名单 claim 映射；个人页列出应用授权并撤销；客户端、用户、服务器停用或恢复 epoch 改变后，旧授权不能复活。已签发 ID Token 为离线 JWT，最长仍可能有效 5 分钟，userinfo/refresh 则即时重验。 |
| 邮箱/手机与恢复 | 实际 SMTP STARTTLS / HTTPS 短信 webhook 投递；验证码 5 分钟、5 次尝试、60 秒发送间隔；挑战绑定浏览器、用户及配置版本；消息加密排队，投递成功或最终失败后清除密文；地址必须完成验证。短信登录沿用 MFA；密码恢复撤销旧会话与凭据，保留 MFA 和恢复码，不自动登录。 |
| 管理员防锁死 | 当前管理员须在 15 分钟内以备用方式完成真实登录及 MFA，才能关闭本地密码登录；后续配置、解绑、停用、凭据撤销等变更在提交前串行重验最后管理员通路，覆盖两个管理员并发解绑；隔离恢复重新开启本地登录。 |
| 运维恢复 | `nt enable-password-login --operator <本地操作人> --reason <至少5字符原因>`，无需修改数据库，操作进入审计；不会取消 MFA。 |
| 前端 | `/info`、`/x-info` 的联合身份、LDAP、联系方式与应用授权 tabs；`/setting` 的提供方、验证恢复和登录策略；`/oidc-client`；`/oidc/server/consent`；两个公开回调兼容入口；能力门禁及身份变化缓存清理。 |

短信渠道选用明确、可自建的 HTTPS webhook 适配契约：Bearer 密钥认证，POST JSON `id/to/text`，`Idempotency-Key` 与 id 相同，成功响应 `200 {"accepted":true}`；平台拒绝明文 HTTP、跳转、错误证书和未确认接收。此适配器不宣称实现未配置的商业短信厂商私有 API。生产网关应实现幂等投递；已有内网 fixture-services 新增 `/sms/send`，可实际接收模拟短信。
