# 批量访问授权

beta0.10 起支持批量访问授权。

入口：**访问控制 → 资源授权 → 批量授权**。

支持两种选择顺序，结果一致：

- **为用户 / 部门选择资源**：选择一个或多个用户、部门，再选择多个资产或分组。
- **为资产 / 分组选择人员**：先选择资产或分组，再选择多个用户、部门。

用户和部门可以同时选择；主机资产、资源分组、网站及数据库可以同时选择。每个所选用户或部门都会获得每个所选资源的授权。提交前显示组合总数，每类最多选择 100 个对象，每批最多 500 条授权关系。例如，2 个用户加 1 个部门，选择 4 个资源，共处理 12 条关系。

## 操作示例

1. 将用户“小王”一次授权给“测试 Linux”“测试 Windows”和“研发资产组”：选择 1 个用户、3 个资源，确认 3 条关系后提交。
2. 将“生产数据库组”授权给“小王”“小李”和“运维部”“研发部”：选择 2 个用户、2 个部门、1 个分组，确认 4 条关系后提交。
3. 为这些授权统一设置开始时间、到期时间和适用的动作策略。时间按浏览器所在时区输入；留空表示立即生效或长期有效。

## 生效与重复处理

- 全部主体、资源、策略和有效期先校验；任何无效引用都会拒绝整批操作并给出原因。
- 全部授权及审计记录在同一事务中提交，数据库或审计失败时整批回滚。
- 用户/部门与资源之间已有未撤销的授权会跳过，包括已到期和审批生成的授权；不会覆盖原策略、到期时间，也不会自动续期。需调整时编辑原授权，审批授权继续遵循原审批规则。
- 重复选择自动去重，并发提交或网络重试不会重复创建相同关系。分组与单个资产是不同的显式关系，不会因为有分组继承就自动合并。
- 完成后显示新增、跳过数量及逐项结果。原有单条新增、编辑、撤销入口保留。
- 部门授权作用于直接所属成员；分组授权动态覆盖子分组，沿用现有访问检查。
- 动作策略和 SSH 命令过滤仅用于非数据库资源；混合批次中的数据库条目不写入这些策略，数据库写入仍需原有权限及审批。

## 接口

`POST /api/admin/grants/batch`，要求 `identity.manage`，在事务内重新验证权限。

```json
{
  "userIds": ["用户UUID"],
  "departmentIds": ["部门UUID"],
  "resourceIds": ["资产或分组UUID"],
  "strategyId": "",
  "commandFilterId": "",
  "expiresAt": null
}
```

可选 `validFrom` 和 `expiresAt` 使用 ISO 8601 时间；省略 `validFrom` 时整批使用同一开始时间。成功响应包含 `total`、`created`、`skipped` 和逐项 `items`，项状态为 `created` 或 `skipped`。不接受审批编号或既有授权 ID，不能借批量接口修改审批授权。
