## 复现

在仓库根目录、PowerShell 7 下执行。先使用现有 compose.env；不要把密钥填入聊天或命令输出。

```powershell
# 编译隔离演练使用的测试二进制
docker compose --env-file backend/.local/compose.env -f backend/compose.yaml --profile test run --rm tests sh -c 'CGO_ENABLED=0 go test -c -o /src/.local/r11-application.test ./internal/application'

# 双服务恢复与回退；使用已构建的新 server / graphics 镜像
./scripts/test-r11-restore.ps1

# 独立物理恢复演练
docker build -t nt-r11-pitr-fixture -f backend/fixtures/pitr/Dockerfile backend/fixtures/pitr
$r11TestBinary=(Resolve-Path backend/.local/r11-application.test).Path
docker run --rm --network none -v "${r11TestBinary}:/fixtures/r11-application.test:ro" nt-r11-pitr-fixture
```

S3 使用支持 multipart 的内网协议模拟器，SFTP 使用真实 SSH/SFTP 协议测试服务，WebDAV 使用认证文件服务；不将这些结果描述为已经完成某家公有云的验收。

## 用户可直接测试

1. 编辑范围、时间与保留策略，检查身份验证和离线持钥证明。
2. 点击立即备份，确认维护提示，观察任务完成；下载加密归档并核对大小和 SHA-256。
3. 为自有 S3/SFTP/WebDAV 配置目标并测试连接，再创建备份观察复制记录；失败时重试。
4. 按[恢复操作说明](../implementation/backup-restore.md)在隔离环境运行脚本，确认冻结、开放前回退、开放后重新登录和恢复记录。

本机开发验收私钥保存在 backend/.local/r11-offline/recovery.agekey，未提交 Git，也不由网页提供。使用该公钥创建的归档必须保留这份对应私钥，并另存独立安全位置。恢复入口使用 CLI，不在网页上传私钥或直接覆盖在线数据库。
