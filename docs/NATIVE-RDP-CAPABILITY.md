# 原生 RDP 能力识别（rc13）

**只使用网页内 RDP 时，无需原生 Worker。** 网页连接使用 guacd；“当前节点为 Linux”描述的是后端容器系统，“未部署原生 RDP Worker”不会阻止网页内 RDP。先按[网页内 RDP](BROWSER-RDP.md)配置资产和图形服务。

入口：**平台配置 → 服务部署 → 监听与证书**，地址 `/deployment-settings?section=listeners`。统一“预检与服务状态”中也可查看原生 RDP 的四维状态及检查项。

本阶段提供能力识别和只读预检。普通生产 Compose 没有原生 RDP Worker，开关默认允许也不会安装它或开放端口。页面明确显示未部署及原因；原生 RDP 不接入通用宿主端口自动部署。浏览器 RDP/VNC 的 guacd 是另一套组件。

## 前置条件与限制

| 条件 | 检查内容 |
| --- | --- |
| 平台与运行状态 | Linux；节点不能处于恢复隔离或维护状态 |
| 部署配置 | 启动前登记原生 RDP 地址、Worker、FFmpeg、证书与私钥路径；这些路径由部署管理，不能从平台配置提交任意命令或文件路径 |
| 监听范围 | 普通部署仅回环；现有 `windows-local` 显式本机容器 profile 可在容器内监听，但宿主端口仍应回环映射，不等于支持公网部署 |
| Worker | 文件可执行；显式预检运行 `--capabilities`，验证协议版本 1 和只读录屏模式声明 |
| FFmpeg | 文件可执行；显式预检运行 `-hide_banner -encoders`，确认可运行并提供 `libx264` |
| TLS 身份 | 证书和私钥可读、大小受限、格式与配对有效；证书覆盖客户端地址且处于有效期 |
| 容量 | 显示当前占用、总量和剩余名额；当前实现最多两个原生会话，检测不预留名额 |
| 进程端口 | 显式预检临时准备候选监听后立即释放；复用已存在的同地址监听，不更改现有连接或提交配置 |

部署变量沿用 `NT_NATIVE_RDP_LOOPBACK`、`NT_NATIVE_RDP_WORKER`、`NT_NATIVE_RDP_FFMPEG`、`NT_NATIVE_RDP_CERT`、`NT_NATIVE_RDP_KEY`。例如 Linux 专用节点的回环入口可以是 `127.0.0.1:13389`；若客户端地址配置为 `rdp.example:13389`，证书须覆盖 `rdp.example`。可用性仍取决于客户端到该入口的实际路径。

本机 Windows 容器验收继续使用 `backend/compose.native-rdp-host.yaml` 的 `windows-local` profile，宿主映射为 `127.0.0.1:13389:13389`。本能力检测不会修改该映射，也不验证防火墙、云安全组、DNS 或公网可达性。

## 使用步骤与状态

1. 打开监听与证书页面，展开“查看 Worker、编码器、证书与容量检查”。普通生产部署会显示未部署；不能据此页面的原生 RDP 开关推断能力可用。
2. 管理员点击“原生 RDP 能力预检”。需要 `identity.manage` 权限；只读账号可查看状态。检测针对**已保存配置**，有配置版本校验，不检查尚未保存的编辑内容。
3. 查看运行能力检查、进程端口检查和最终分项结果。任务持久保存，刷新可继续查看；可在统一状态页取消预检，取消后的结果不会被迟到的检测覆盖。
4. 修改监听配置仍走原有保存和节点应用流程；客户端公开地址也纳入保存前的候选监听检查。能力预检不会绕过 TLS、回环监听、身份验证、资产授权或录屏要求。

“静态条件通过”仅表示文件、证书、模式和当前容量满足检查。Worker、编码器是否能执行由显式预检证明；“监听存在”仅指当前节点实际监听，尚未确认最新配置或依赖异常时显示部分异常。能力预检成功不代表目标 Windows 登录、完整会话、文件策略、录屏存储或公网连通已经验收。

预检证据有效期五分钟，绑定配置版本与节点；程序重启、配置改变或已检查的 Worker/FFmpeg 文件元数据、证书和部署参数变化会使旧证据失效。动态库更新等未改变登记文件的变更需要重新检测。证书失效、维护状态及容量满会在最新报告中阻止就绪判断。状态刷新失败显示过期，不能沿用绿色成功状态。

## 安装升级兼容

普通一键安装及升级不增加原生 RDP 容器或宿主端口，继续明确报告能力不足。专用部署需同时更新后端、前端与 Worker；新 Worker 的 `--capabilities` 在创建控制连接、临时目录或录屏之前直接返回固定能力 JSON。旧 Worker 没有该接口时，预检报告不支持检测协议；不自动替换或启动会话。

无新增数据库迁移，持久任务沿用迁移 108，该能力首次在能力版本 88 接入；当前源码 schema 110、能力版本 90。`native-recording-test.Dockerfile` 新增可选 `NT_RDP_WORKER_IMAGE` 构建参数，默认镜像不变，可在隔离验收时选择匹配的 Worker。

## 开发验证

2026-11-15：缺项、回环限制、证书配对/SAN/有效期、维护状态、容量、错误脱敏、端口占用、监听保留、证据失效及无宿主执行器场景通过；相关应用测试使用隔离 PostgreSQL 并启用 Go race。真实 Worker 能力协议在只读、无网络容器通过，真实 FFmpeg 编码器探测及原生认证、只读桌面录屏回归通过。

前端 16 项相关测试、生产构建、后端 Windows 交叉编译及 Go vet 通过。浏览器使用受控接口数据验证预检进度、刷新恢复、未部署提示、只读账号权限、窄屏布局、旧服务端兼容和刷新失败后的过期状态；该页面验证与上述真实后端集成验证分别执行。证书路径为命名管道时的拒绝检查通过，避免状态查询因非普通文件阻塞。

这些验证不代表 Windows mstsc 整机验收或公网部署认证。当前功能已随 rc13 发布，但不会自动更新远程服务器；共享盘 AppArmor 内核强制访问及整机安装升级等既有发布门槛仍保留。
