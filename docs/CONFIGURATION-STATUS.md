# 统一配置状态与只读预检（P1-0）

开发分支功能，尚未发布到远程服务器或正式镜像。

## 页面入口

“平台配置 → 状态与发布 → 预检与服务”。配置总览和各配置分组也提供快捷入口。服务端通过 `system.settings.operations` 能力声明此功能；旧服务端不会出现该页签。

页面分开显示用户期望、配置应用、依赖就绪和实际服务。可按部署、外部依赖、业务策略筛选，展开查看检测范围、原因、修复建议、版本及有效期。配置节点表保留离线和不同步状态。历史预检成功不等于当前就绪；状态刷新失败时，之前的状态标记为证据过期。

## 当前支持范围

- MySQL、PostgreSQL、网站 HTTPS、SSH、管理 HTTP：复用 P0 应用检查和宿主执行器预检。检测当前保存配置及已登记的宿主映射，不接受候选配置或任意目标地址。
- 浏览器 RDP/VNC：接管后的内部 guacd 支持只读部署预检；实际状态分别来自宿主容器观察和应用到 RDP/VNC 插件的握手。外部或旧执行器不支持时显示原因，不推断目标资产可用。见 [图形组件自动部署](GRAPHICS-AUTO-DEPLOYMENT.md)。
- RDP 共享盘：读取独立部署期望及实际挂载；启用前检查 FUSE、图形健康、存储配置卷及 AppArmor。部署时另外验证挂载读写；关闭不删除 MyZone 数据。
- 当前节点的监听管理器提供实际监听证据。监听存在但当前节点未确认最新配置时显示部分异常。此结果不证明用户权限、目标资产或公网可达。
- 显示最近部署任务的阶段与结果，并链接到既有部署页面。真正的部署仍使用原有密码/MFA 复核、版本校验、重新预检、进度票据与失败恢复流程。
- 邮件、LDAP、OIDC、企业微信、Passkey、默认模型、受控转发和 DML 等仅纳入状态目录，统一依赖检测尚待 P1-2 适配；当前显示未检测，不提供无效的预检按钮。专项检测入口保留。
- 纯业务策略的依赖和运行维度显示不适用，其应用结果来自配置版本与节点确认。

此页不部署组件、不发送邮件、不调用付费模型、不写外部备份，也不处理防火墙或云安全组。首次开放尚无映射的入口，应从“服务部署”填写端口并执行。

## 状态证据与任务

预检证据包含配置版本、进程节点 ID、宿主部署 generation、检测时间、5 分钟有效期、检查项和操作者。任何配置版本变化均保守地使已有证据失效。进程重启生成新的节点 ID；旧节点证据只能作为历史记录。本节点检测优先，不由其他节点的成功记录覆盖。

任务阶段为排队、应用依赖检查、宿主预检、完成；总租期 45 秒。执行结果写入 PostgreSQL，刷新页面可继续查看。进程中断或超时后的任务显示已中断，重新提交时会释放过期占位；只读预检不会自动重放。恢复备份时全部预检证据置为过期。

同一节点、功能与版本的在途重复提交复用原任务；其他并发预检返回冲突。本机探测还受并发槽限制。取消后，不再接受在途探测结果；已经开始的只读网络请求可能持续到超时。取消与完成以数据库状态更新为准，不覆盖已经完成的任务。

预检开始和取消写入审计。持久表保留最新 200 条任务及各功能最后一条证据，历史接口最多返回最近 100 条。统一返回稳定错误码和修复建议，不转发宿主原始错误、配置快照、密码或进度票据。宿主能力不足、未接入、不可达均不显示通过。

预检结果不是部署授权凭据。P0 部署提交时仍重新检查版本和端口，不能凭此页的历史成功记录跳过执行前检查。

## API

| 方法与路径 | 权限 / 行为 |
| --- | --- |
| `GET /api/settings/operations` | `settings.read`；四维状态、当前响应节点、节点确认及最近检测证据 |
| `POST /api/settings/operations/{feature}/preflight` | 管理员且有 `identity.manage`；JSON 空对象，必须带 `If-Match: "settings-版本号"`；返回 202 和持久任务 |
| `GET /api/settings/operation-tasks` | `settings.read`；最近 100 条预检记录 |
| `POST /api/settings/operation-tasks/{id}/cancel` | 管理员且有 `identity.manage`；取消只读预检，不取消部署任务 |

统一响应协议 `version=1`。返回的节点范围是当前响应进程，并非跨节点主动探测汇总。多节点配置应用情况由单独的节点确认列表呈现。预检证据与实际监听状态不可相互替代。

## 安装、升级与验证

新增数据库迁移 `108_configuration_checks.sql`，服务端按原有迁移流程创建任务表。能力版本升为 84。此阶段无需新增容器、宿主端口或部署参数；五类入口预检需要 P0 配套执行器已接管。安装/升级脚本不需要为此增加手工步骤。发布时必须使用匹配的前后端镜像，升级前仍按既有流程备份。

测试覆盖证据版本/节点/generation/有效期、策略隔离、权限、并发复用及互斥、取消防覆盖、错误脱敏、节点离线、进程重启后的旧证据失效、过期租约恢复与备份恢复隔离。后端应用测试使用隔离 PostgreSQL 和 Unix Socket 执行器夹具，宿主执行器自身回归独立运行。浏览器 API 夹具用于验证进度、刷新、取消、断线提示及权限，不能替代真实外部依赖验收。

后续已接入图形组件、RDP 共享盘及 MP4 渲染器，当前能力版本为 89；组件状态结合宿主实际观察，MP4 另有只读认证探测。开发进度见 [开发计划](CONFIGURATION-AUTOMATION-ROADMAP.md)。

本轮验证结果：配置状态单元测试、7 项应用集成场景、宿主部署执行器及系统模块回归通过，`go vet` 通过；22 项前端回归、完整类型检查和生产构建通过。浏览器 API 夹具验证预检进度、重载恢复、取消、断线失效、只读权限及窄屏布局通过。未执行远程发布或生产环境验收。

原生 RDP 已接入节点级能力预检，不要求宿主部署执行器。报告包括部署模式、程序、TLS、容量和实际监听；显式预检执行有限的 Worker/编码器查询并临时验证进程端口，见 [能力识别说明](NATIVE-RDP-CAPABILITY.md)。

## P1-2 与 P2 扩展

外部依赖现已支持固定配置和资源详情的共享四维面板，新增迁移 109 保存备份验证的加密清理记录。资源证据额外绑定资源版本、引用与操作者；读写验证不可取消，清理失败由后台恢复。范围与 API 见 [外部依赖预检](EXTERNAL-DEPENDENCY-CHECKS.md)。

P2 的 Agent 仓库、WAL 和入口策略在服务部署页使用宿主持久任务和独立进度通道；实际服务状态结合容器健康、已验证部署摘要及 WAL 调度结果。任务不属于只读预检取消接口。见 [专项运维自动部署](OPERATIONS-AUTO-DEPLOYMENT.md)。
