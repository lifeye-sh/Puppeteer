# R16 许可与配额操作说明

本批实现 schema70 的用户、资产与远程会话准入配额。R16 整轮完成状态见 [验收记录](R16.md)；本说明不代表其他配置适配、DBeaver 或全站按钮矩阵已验收。

## 平台设置

管理员进入 `/system-status` 查看“部署许可与配额”：显示来源、有效状态、到期时间、实例 ID，以及三项配额的使用量、上限、剩余量。每30秒刷新，也可手动刷新。

- 用户：所有未删除账号，包含停用账号。初次初始化允许创建唯一恢复管理员，之后新增管理员也受限。
- 资产：未删除主机、数据库和网站总数，包含停用资产；分组不占额度。手工新建、批量导入和 LDAP 用户同步走同一个事务检查。
- 会话：本实例当前认证 epoch 中有效租约的主机终端和 MySQL/PostgreSQL 连接。浏览器登录不计入；它有独立的每用户登录数量配置。

`null` 表示不限，0表示不允许净新增。删除释放用户/资产名额；编辑和降低现有配置不删除数据。会话正常结束释放名额；断线或进程异常通过租约超时释放。降低会话配额仅阻止新增，不任意断开已存在会话。许可到期或协议权益撤销则在下一次续租拒绝。现有主机16全局/4每用户、数据库每节点64等运行保护上限仍独立生效，许可“无限”不取消这些保护。

所有节点的创建和续租在 PostgreSQL 中共用事务级配额锁。租约判断使用数据库实际当前时间，防止等锁后使用旧事务时间复活过期租约。数据库连接建立预留75秒，存活连接每5秒复核并续租15秒。过期数据库会话由维护任务每秒结算，每批最多100条，进行中的 SQL 标为结果未知；已完成日志保留。

## 部署配置

默认不设置任何变量，等价 `NT_ENTITLEMENT_MODE=local`，沿用已实现功能和不限配额。部署到业务服务时继续使用此默认值。**本轮测试不在业务实例导入限制许可，也不修改现有用户数量限制。**

需要本地配额时，将管理员维护的 JSON 文件只读挂载至容器，设置 `NT_ENTITLEMENT_LOCAL_FILE` 为容器内路径，重启本项目服务生效。所有连接同一数据库的节点必须采用同一份文件与模式，不能混用不同配额。示例：

```json
{
  "features": {
    "identity.users": true,
    "resource.assets": true,
    "session.ssh": true,
    "session.telnet": true,
    "session.rdp": true,
    "session.vnc": true,
    "database.mysql": true,
    "database.postgres": true,
    "ai.assistant": true,
    "automation.execute": true,
    "notification.send": true,
    "files.write": true
  },
  "quotas": {"users": 100, "resources": 1000, "sessions": 20}
}
```

非空配置必须提供 features 和三项 quotas，缺失功能键视为未授权。这里 identity.users 约束新增用户，resource.assets 约束新增三类资产；它们不禁止查看或编辑已有记录。其他协议键约束创建、消费终端票据和续租。revision47 起 ai.assistant 约束新建对话、模型推理/探测及 AI 工具提案、批准和执行。revision48 起接入任务执行与凭据轮换、业务通知发送和文件写入独立权益。必要登录/恢复验证码豁免notification.send；读取/导出、取消和恢复入口保留。

### AI 权益（revision47）

默认 local 空配置继续允许现有 AI 功能，不修改模型、预算或资产授权。采用非空本地配置或签名许可的部署，必须显式包含 `ai.assistant: true`；缺失视为未授权。管理员仍可维护模型配置，但模型发现需要许可。许可不会自动开启 AI 系统总开关、资产访问或工具审批。

`ai.chat` 表示工作区入口，许可失效时保留；`ai.inference`、`ai.stream`、`ai.queue`、`ai.tools`、`ai.models` 随 AI 权益关闭，前端禁用发送、模型发现和工具执行。历史对话、用量、配置、拒绝、取消与删除继续经过原有身份/所有权校验，不因许可失效而放开跨用户访问。

外部模型调用前再次检查许可，并每500毫秒复核，单次检查超时2秒，检查失败按拒绝处理。撤销后取消请求传输；不能保证模型服务未产生费用，也不能撤回已经展示的片段。最终历史会标记权限变更并清除答案。工具执行沿用250毫秒复核；已经发生的远端副作用无法撤回，结果未知必须人工核查，不自动重试。

未调用模型就被拒绝的排队任务记录 `ai.turn_finished / dispatch=not_started`，结算为已知零用量并释放预占预算；已经派发且用量未知的请求保留保守预占，已知用量正常结算。队列拒绝会清除加密授权载荷。完成请求的相同幂等重放只返回历史结果，不产生新模型调用。

签名模式使用 `NT_ENTITLEMENT_MODE=signed`，只读挂载信任公钥文件，设置 `NT_ENTITLEMENT_TRUST_FILE`，不得同时设置本地配置文件。文件结构为 `{"keys":{"发行者kid":"32字节Ed25519公钥的标准Base64"}}`，支持1至16个公钥。服务端不接受私钥。模式、文件内容或公钥无效时启动失败，不回退为无限许可。未导入签名许可时，新建和连接被阻止，管理员仍可登录并导入。

导入入口为平台设置的“导入签名许可”，粘贴本项目签发、属于页面实例 ID 的 compact JWS，输入管理员密码；已启用 TOTP 时还需验证码。页面和接口不能切换模式或设置公钥。过期、篡改、错实例、错发行者、未知算法、重复 JSON 成员均拒绝。提交携带当前修订，别人先导入会返回409；刷新后重试。签名历史由服务追加，审计只记修订和 SHA256，普通查询不返回许可正文。

签名格式详见 [D05](../implementation/settings-entitlements.md)。签发私钥由部署所有者在离线环境保管，本项目不接收、转换或仿造第三方许可。许可每次准入和续租重验时间及实例，不做无限期缓存。允许60秒时钟偏差；离线模式不能保证检测主机时钟恶意回拨，不能即时撤销已经离线的签名。

## 到期、恢复与回退

登录、读取审计、删除资源和备份恢复入口不受上述权益关闭影响。已初始化实例不能利用“创建管理员”绕过用户配额。隔离恢复产生新实例 ID / epoch 后，旧实例签名不再适用，旧租约也不能续租；需要部署管理员为新实例提供有效配置或签名。

导入只追加许可修订并更新 head，不修改旧修订。收紧许可时，已经通过准入且尚未提交的创建事务可能完成；后续新事务和会话续租采用新许可。配额降低保留已有资源，所以使用量可以合法地超过新上限。

schema70 新增 entitlement_licenses、entitlement_head 和主机/数据库会话 epoch、数据库租约字段。部署前必须验证备份并保留旧二进制；不通过覆盖业务库进行回退。数据库迁移后不要直接换回旧版服务并声称配额仍受保护。按 R11 隔离恢复流程验证需要恢复的备份。


### 独立共享盘进程

server 与 guacd 内的 nt-rdp-storage 必须使用相同 NT_ENTITLEMENT_MODE、NT_ENTITLEMENT_LOCAL_FILE、NT_ENTITLEMENT_TRUST_FILE 及只读挂载文件。compose.r16.yaml共用这三个环境变量；非默认部署须在两服务中挂载同一策略/公钥文件。路径非空但文件缺失/为空/无效会启动失败，不回退无限许可。默认local空配置仍允许已实现功能。
