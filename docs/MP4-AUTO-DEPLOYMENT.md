# MP4 渲染器自动部署（r17-rc13）

入口：**平台配置 → 服务部署 → MP4 渲染**，地址 `/deployment-settings?section=mp4`。需要管理员身份、`identity.manage` 权限及密码/已启用的动态口令复核。录屏策略仍在业务策略中管理；允许录屏不代表渲染器已就绪。

## 适用部署

匹配版本的安装和升级程序会自动接管生产 `services.yaml` 中的内部 `mp4-renderer`，记录 `x-puppeteer-mp4` 和组件所有权。保留已登记的镜像、密钥文件及应用数据卷。外部渲染地址、自定义端口、额外设备/挂载、启动命令和不兼容资源配置不自动改写，页面解释不支持原因。

渲染器只接入项目内部 `render` 网络，监听容器内 `8090`，**不映射宿主端口**。后端地址为 `http://mp4-renderer:8090`，双方使用同一文件 secret `/run/secrets/mp4_token`。默认资源约束沿用生产配置：只读文件系统、移除 capabilities、no-new-privileges、768 MiB `/tmp`、2 GiB 内存、2 CPU、160 PID。

本功能需要包含 MP4 部署能力的 server、web、宿主执行器和接管脚本。已发布的 r17-rc11 不包含此功能。核心部署没有渲染器配方时显示能力不足，不能凭空生成密钥或替换外部服务。

## 操作与队列策略

1. 选择期望状态，输入复核信息，点击“预检并执行”。修改前检查组件所有权、内部网络、密钥来源、资源限制、缓存持久化卷、权限和至少 512 MiB 可用空间；恢复隔离期间拒绝变更，预检不创建渲染任务。
2. 执行器持久化任务及恢复配置，再应用变更。操作会重建后端与网页容器，现有连接会中断；进度可在独立通道继续读取，刷新后可恢复。
3. 停止后端接收新转换并停止唯一工作进程，再停止渲染器；验证工作进程确已退出后，幂等整理 MP4 队列。未完成转换回到待处理，不因部署消耗重试次数；已取消的任务保持取消，失败和成功任务保持原状态，其他类型任务不修改。
4. **开启**：拉取缺失的已登记镜像，启动渲染器并等待健康；验证匿名请求被拒绝、应用密钥可认证；实际转换 500 ms 内置文本样例并检查 MP4 文件标识，清理样例。通过后恢复后端与队列，验证容器、应用接入地址和认证。
5. **关闭**：清空后端 `NT_MP4_URL`，将渲染器放入 `puppeteer-mp4-disabled` profile；普通 `puppeteerctl up -d` 不会重新开启它。验证容器停止、新任务入口关闭及内部端口不可连接。

停用策略是**暂停并保留**。已排队或正在转换的任务保留，重新启用后从源录屏重做未完成转换。原始录屏及现有缓存不被部署操作删除；授权用户仍可下载已生成的 MP4，未授权用户仍被拒绝。现有录屏保留和缓存到期策略继续有效，不能把“保留”理解为无限期保留。

## 状态和失败恢复

统一状态页分开显示期望状态、配置应用、依赖预检、实际服务。实际服务参考容器健康及当前后端认证探测；只读状态查询不产生样例任务。渲染能力以最近部署时的实际样例验证为准，不能保证所有用户录屏均可转换。

开启失败恢复之前的部署配置；关闭失败尝试保持关闭，先停止工作进程与渲染器，再整理队列并恢复关闭配置。执行器重启继续根据持久化任务恢复。遇到 Docker/数据库不可达，任务保留具体失败阶段，不能把恢复失败报告为成功。不要通过手工启动渲染器绕过失败原因。

升级通过相同接管逻辑保留 `puppeteer-mp4-disabled`、空接入地址、通信密钥、镜像与数据目录。正常页面启停不操作防火墙或云安全组，也不修改宿主端口。

## 开发验收

- Go：部署配方拒绝不兼容项、顺序与存活工作进程保护；只读认证与样例清理；数据库队列幂等、取消和终态保护；真实转换、缓存下载授权与停用后下载。
- Docker：`python tests/deployd_docker_integration.py --mp4 --recovery --server-image <匹配测试镜像>` 验证启停、真实样例、普通启动保持关闭、开启中断恢复、关闭中断保持关闭、队列及缓存保留；`--systemd` 单独验证镜像内接管脚本及 systemd 管理。
- 前端：生产构建、导航状态测试，以及浏览器中的组件表单隔离、无端口输入、预检失败不提交、进度刷新、旧执行器禁用和移动端布局。

功能已随 r17-rc13 发布。发布镜像的实际编码与安装升级验证范围见[发布说明](../deploy/production/r17-rc13.md)；Docker Desktop 隔离验收不代表所有远程宿主机环境均已验证。
