- P2 三项已落地：签名 Agent 更新仓库、PG18 WAL/隔离恢复/定时备份、Nginx 入口策略；含预检、进度、失败恢复和安装升级接管。见 [专项运维自动部署](OPERATIONS-AUTO-DEPLOYMENT.md)。

- 宿主自动化继续限定支持的单机 Docker Compose 环境。只检查监听和端口占用，不管理防火墙、云安全组或 DNS；不能由本地端口验证推断公网可达。

旧 `/system-status?section=...` 自动跳转对应分组，保留其他查询参数；不带 section 的地址进入配置总览。账号、权限与功能能力决定可见项，直接访问没有可用项的分组显示拒绝访问；前端展示不替代服务端授权。

## 开发顺序与交付门槛

### P1-0：统一预检、状态和进度基础（已落地首批适配）

先复用已有部署任务、配置版本和各专项检测接口，定义适配层，避免给所有功能套用宿主执行器。

| 维度 | 证据与展示要求 |
| --- | --- |
| 用户期望状态 | enabled / disabled / configured，包含配置版本、目标资源、作用范围和提交人 |
| 配置应用状态 | pending / applying / applied / failed；区分在线节点确认、离线节点和部分节点失败 |
| 依赖就绪状态 | unknown / checking / ready / blocked / stale / not_applicable；关联检测时间、配置版本、节点、检查项和有效期 |
| 实际服务状态 | unknown / starting / running / degraded / stopped / failed / not_applicable；以当前运行探测或业务验证为证据 |

每项检查返回稳定的错误码、用户可读原因、修复动作、检测范围和时间。连接成功不等于认证成功；认证成功不等于规则匹配或有资产权限。密钥、密码、令牌和含凭据 URL 不得出现在错误或进度日志中。修改相关配置后旧检测变为过期；不同节点、旧版本的成功结果不能覆盖当前失败。纯策略项的无关维度明确显示“不适用”。

任务流程：预检 → 执行计划 → 应用配置/部署 → 验证 → 完成，失败进入恢复或保持关闭。记录任务 ID、版本、操作人、阶段时间和分项结果；已受理任务可在刷新或 API 短暂离线后继续追踪。只读预检与可能发邮件、产生模型费用、写备份文件、签发证书的业务验证分开，后者必须由明确操作触发。

沿用 P0 的互斥、版本冲突、幂等与持久化能力，明确每种任务的可取消阶段、重试规则、执行器中断恢复、开启失败恢复及关闭失败保持关闭策略。旧节点不支持时返回能力不足；避免混合版本下静默跳过检查。检查通过后到执行前重新确认版本及端口，消除预检与提交间的竞争。

验收：过期预检、节点部分失败、权限不足、重复点击、并发改配置、API 失联、进程重启、敏感错误脱敏均有覆盖；菜单、页面与 API 权限一致。此基础通过后再按下面顺序接入能力。

### P1-1：组件部署

| 顺序 / 项目 | 前置检查与执行 | 成功及失败验收 |
| --- | --- | --- |
| 1 图形服务 guacd（已落地） | 镜像与版本、内部网络和后端地址；自动配置与启停组件；明确提示并中断现有连接 | 内部健康、协议握手和代表性会话验证；依赖不可达明确失败；停用处理会话并验证新连接被阻止 |
| 2 RDP 共享盘 / MyZone（代码与 FUSE 验收已落地） | 宿主 FUSE、/dev/fuse、AppArmor 能力、最小挂载权限、storageconfig 卷及归属；安装匹配策略和挂载 | 真实挂载及受控读写验证、卸载与句柄释放；宿主能力不足在修改前拒绝，不能仅以文件传输策略开启验收 |
| 3 MP4 渲染与下载（已落地） | 渲染器、内部网络、地址、通信密钥、磁盘空间和资源限制；部署后做小样本渲染 | 渲染与授权下载验证；停用先阻止新任务，排空或按明示策略处理队列；保留原录屏及失败任务，不丢失待处理数据 |
| 4 原生 RDP 能力识别（已落地） | Worker、FFmpeg 可执行文件、TLS 身份、运行 profile、容量及监听地址 | 显示支持/不支持及具体原因；保留普通部署回环限制与显式容器 profile 限制，本阶段不承诺通用公网自动部署 |

每项同时更新生产 Compose、安装/升级接管、回滚及操作说明。涉及重建的连接中断影响应在操作前显示；外部自建组件须识别所有权，不能被默认删除或替换。共享盘的宿主特权使用受限执行器，不能扩展成任意命令执行。

### P1-2：外部依赖统一预检（已落地）

已按 A → B → C 接入。只读预检检查已保存配置，保留各功能原有保存/启用保护；实际投递、模型调用、授权和签发须通过明确业务操作验证。

| 批次 / 项目 | 预检及验收重点 | 页面归属 |
| --- | --- | --- |
| A 平台邮件与通知 | DNS/网络、TLS/CA、SMTP 认证、发件人；显式测试投递；分别显示渠道启用、可投递、接收人绑定和规则匹配 | 外部依赖 / 通知渠道与规则 |
| A LDAP | CA、连接、服务绑定、Base DN、查询、不可变身份属性及映射；同步计划作为业务任务独立启停 | 外部依赖 / 身份认证 |
| A OIDC 与企业微信 | 发现文档或应用参数、客户端凭据、回调、授权与身份映射；外部提供方后台配置没有管理能力时显示待完成项 | 外部依赖 / 身份认证 |
| A Passkey | HTTPS 来源、RP ID、域名关系；服务端检查与当前浏览器支持分开；实际注册仍由用户完成 | 外部依赖 / 个人账号 |
| B AI 助手、模型、工具和审计分析 | API/协议/代理、凭据、许可及预算；策略允许、模型连通和当前可调用分别展示；调用验证显式触发；工具不新增资产权限或绕过审批 | 外部依赖 / 业务策略 / AI 助手 |
| B 备份自动复制 | S3/SFTP/WebDAV、目标路径、CA/主机指纹、权限；复用读写、摘要、清理测试，使用隔离测试对象 | 备份与恢复 |
| B ACME | 账号、DNS-01、RFC2136/TSIG、网络及域名；复用订单和签发日志，检查挑战清理及续签失败；不以布尔开关替代成功订单 | 证书管理 |
| C OIDC 服务端与原生客户端 | 固定 Issuer、签名密钥、HTTPS 发现文档、客户端注册、用户权限及各协议入口；无需创建专用端口 | 外部依赖 / 应用与原生接入 |
| C SSH 受控转发 | 网关实际状态、精确目标规则、资产权限和目标网络；撤销后验证转发终止，不创建宿主公开映射 | 外部依赖 / 访问控制 |
| C 数据库原生 DML | 数据库代理、独立 DML 凭据、资产模式与用户写权限；关闭后核验写会话终止及事务结果，不删除共享代理端口 | 外部依赖 / 数据库资产 |
| C Agent、跳板、网关组、网络代理 | 心跳/连通、凭据、引用及受影响资产；与已有安装任务关联，未部署需显示原因 | 接入管理 |

原生 DML 遵循当前实现边界：MySQL 受控写入、PostgreSQL 只读；SQL 工单审批执行独立。新统一界面不扩展协议写入能力。

### P1 关联补项：网站间接链路（已落地）

网站自动启用预检支持直连，以及 Agent、跳板、网关组和网络代理的实际出站路径；检查 TCP/TLS、目标证书、资源版本和操作授权。链路不具备可验证能力时继续阻止启用，不能用本机直连成功代替。覆盖多网站共享网关以及关闭、删除时的引用竞争。本项依赖上述资源连通预检，不替代组件与通用预检开发顺序。

### P2：专项运维自动化（已落地）

| 项目 | 自动化内容 | 必须满足的退出条件 |
| --- | --- | --- |
| Agent 更新仓库 | 验证签名与版本、原子发布更新文件、导出只读目录、配置 HTTPS/Nginx 挂载 | 下载可达、签名验证、失败回退；不发布未验证文件 |
| WAL 归档 / PITR | 专用 PostgreSQL 镜像、归档卷、加密密钥、stanza、备份任务及保留策略 | 首份备份、连续归档和隔离恢复演练成功后才显示可恢复；迁移与回滚不损坏数据库卷 |
| 网页入口访问限制 | 生成 Nginx 策略、语法检查、应用与入口验证 | 验证当前管理员可访问和恢复通道，防止误封；失败恢复原策略 |

P2 已通过隔离 Docker 实测：入口策略放行/拒绝、签名发布实际下载与停用、WAL 首份完整备份和命名恢复点演练、关闭保留密钥/数据、任务中断恢复及残留清理。应用进程恢复隔离时暂停后台 WAL 任务。真实远程安装升级和发布仍为交付门槛；本地库恢复链路不等于完整应用或异地灾备。

## 纯业务策略的接入边界

| 类别 | 纳入范围 | 生效要求 |
| --- | --- | --- |
| 登录安全 | 验证码、失败锁定、强制 TOTP、关闭本地密码登录 | 保留备用登录验证、敏感复核及最后一个管理员登录方式保护 |
| 会话策略 | 数量、空闲、Cookie、接入 MFA | 标明影响新会话还是现有会话，保留收紧/放宽的不同确认规则 |
| 访问授权 | 用户/角色启用、审批、资产授权、访问规则 | 核验引用、撤销和现有连接，不交给宿主部署执行器 |
| 显示策略 | 水印及附加字段 | 标明显示范围及新会话生效条件 |
| 数据保留 | 录屏、日志期限、存储配额 | 录屏策略不代表 MP4 已部署；允许文件传输不代表共享盘可用；保留删除保护 |
| 业务任务 | 定时任务、通知规则、LDAP 同步计划 | 区分规则已启用、计划已调度、最近一次执行结果 |

## 每阶段完成标准

1. 服务端、前端、权限、错误与审计、安装升级及说明同步完成，不能只交付开关。
2. 有正向验证，也有预检失败不变更、执行失败恢复、关闭残留检查、重试/重启和并发覆盖。
3. 自动化涉及真实组件时使用隔离 Docker/Linux 环境验收；页面夹具只能验证交互，不能证明服务已就绪。
4. 发布前确认镜像与脚本版本匹配，完成干净安装和既有数据升级，再发布 GitHub 与镜像。发布记录注明支持平台、限制及迁移步骤。
