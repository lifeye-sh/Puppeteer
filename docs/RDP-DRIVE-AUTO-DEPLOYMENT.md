# RDP 共享盘 / MyZone 自动部署

功能已包含在 r17-rc13 镜像中；远程服务器须执行升级，宿主机仍需满足下列 FUSE 与安全策略条件。

## 操作

管理员进入“平台配置 → 服务部署 → RDP 共享盘”，选择启用或停用，输入管理员密码及需要的 MFA，点击“预检并执行”。页面展示部署配置、实际挂载状态、预检原因和任务进度；刷新或应用短暂重建后可继续查看结果。

开启共享盘前，图形组件须处于启用且健康状态。关闭共享盘会中断现有连接、重建应用及图形容器，恢复后的 guacd 继续提供图形服务。需要继续使用的 RDP/VNC 会话需重新连接。网页 MyZone 文件、空间、配额及授权保留；该操作不删除数据库或存储卷，也不授予任何资产或文件权限。

## 前置预检

- 已接管的单机 Docker Compose，拥有标准内部图形服务及专用存储配置卷；支持的操作不接受任意镜像、命令、设备或宿主路径。
- `/dev/fuse` 为宿主字符设备。缺失时在修改服务前失败，说明环境不支持；不把 UI 操作变成通用内核/软件包安装器。
- 图形服务与应用健康；应用端的 `storageconfig` 卷可写、图形端只读，二者使用同一项目卷。拒绝外部卷、附加宿主挂载、未登记设备、额外权限及自定义启动程序。
- Docker 不处于 rootless 或 SELinux 模式（这两种模式暂不支持自动共享盘）。启用 AppArmor 的宿主必须已有 `apparmor_parser`，先校验固定策略，才允许应用。
- 同名 AppArmor 文件有自定义内容或不安全权限时拒绝覆盖。不关闭 AppArmor，不使用 `privileged`，也不开放宿主端口。

预检只读取运行状态并校验临时候选文件；不加载内核策略、不拉取镜像、不改变服务。镜像拉取、挂载或存储数据库连接仍可能在部署阶段失败，届时进入恢复流程并保留具体阶段。

## 自动执行

启用：停止旧图形进程 → 加载项目专用 AppArmor 策略（宿主启用时）→ 应用共享盘配方 → 重建应用和 guacd → 等待健康 → 验证挂载与读写 → 完成。

共享盘运行程序随宿主执行器升级，作为固定只读文件挂入图形容器，不要求管理员手工替换可选图形镜像。只有 FUSE 守护进程使用 root；guacd 及协议进程保持 UID/GID 1000，不继承数据库环境变量。设备限定 `/dev/fuse`，附加能力限定 `SYS_ADMIN/SETUID/SETGID/DAC_OVERRIDE`，根文件系统只读，挂载带 `nosuid/nodev/noexec/default_permissions`。

停用：先停止旧 FUSE/guacd 进程，再重建不含共享盘的图形容器；移除设备、附加能力、数据库环境与密钥挂载、存储配置卷及运行程序挂载。guacd 直接以 UID/GID 1000 运行，所有能力丢弃，仅保留内部图形网络。验证应用已关闭共享盘入口、实际挂载/设备不存在，并验证图形容器健康。

关闭整个图形服务会同时停止共享盘；单独停用共享盘不会开启原本已关闭的图形服务。重新开启图形服务时尊重最近保存的共享盘期望状态。

操作复用现有管理员授权、密码/MFA、审计、版本校验、互斥、持久任务和独立进度通道。启用失败恢复之前的部署；关闭失败或执行器中断时优先停止旧共享盘进程，再恢复为不带共享盘的配方。如果 Docker 不可用导致无法确认停止，显示失败，不假报完成。

## 状态与读写验证

“状态与发布 → 预检与服务”新增 RDP 共享盘条目。用户期望、配置应用、依赖预检、实际挂载分别显示。普通文件页面将“配置已启用”与“实际挂载可用”分开解释。

实际部署会通过已挂载的 FUSE 路径读写一个 root 专用、最多 64 字节、仅驻内存的诊断 inode，并校验随机内容、清空后关闭。UID 1000 的 guacd 及普通用户无法访问此诊断项；它不创建用户、会话或用户文件，也不绕过用户数据的 ACL。该测试证明挂载读写可用，不代表某台 Windows、某个用户或目标资产已经获得 MyZone 权限。真实用户文件仍经过原有会话、ACL、读写策略、许可和配额检查。

## 安装、升级与边界

- 新安装在首次启动前识别 AppArmor，校验随版本发布的固定策略摘要，自动加载 `/etc/apparmor.d/puppeteer-rdp-storage-<项目名>` 并配置图形服务。
- 升级保留现有镜像和卷；接管程序为兼容的图形配方补充共享盘元数据。之前停用的共享盘状态和原始配方保留，不能因普通 `compose up` 或升级重新启用。
- 已接管部署启用时自动加载上述策略；停用后保留未使用的项目专用策略文件，避免影响恢复及后续启动，不保留容器挂载权限。
- 核心安装缺少图形/共享盘配方，外部 guacd 或自定义宿主挂载不在本阶段接管范围；页面给出原因，不覆盖自建组件。
- 已发布旧版本的手工 AppArmor 修复脚本仅用于其原有部署格式；匹配的新版本使用此自动流程。

## 验收记录

- 单元测试：共享盘启停保持图形状态、移除敏感挂载与权限、拒绝不支持配方、预检失败不修改服务、诊断 inode 的 UID 隔离与写入上限。
- PostgreSQL 集成：统一状态、旧执行器、只读预检、原有文件 API、共享空间 ACL、配额、撤权和通道策略。
- 隔离 Docker：真实 FUSE 挂载读写、诊断文件权限、关闭后的挂载/设备移除、普通启动保留停用、数据保留、VNC 会话中断及执行器中断恢复。
- 实际 systemd：使用镜像内接管程序自动登记并执行上述启停。
- 安装/升级/接管脚本 30 项回归；真实 AppArmor parser 语法检查通过。当前测试宿主未启用 AppArmor，尚未完成启用 AppArmor 的 Ubuntu 内核上的加载与强制访问验收，正式发布前需补齐。
- 浏览器交互使用 API 夹具，验证图形与共享盘表单隔离、预检失败不提交、任务恢复、旧执行器及窄屏；不以界面夹具代替挂载测试。
