# Puppeteer r17-rc12 源码候选版本

日期：2026-11-15。平台：Linux amd64。数据库 schema 110，能力版本 90。

本版本提交源码及版本标签，尚未发布配套 Docker Hub 镜像。已发布镜像仍为 r17-rc11（schema 107）；一键安装和镜像升级默认目标保持 r17-rc11。不要执行 `upgrade.sh --version r17-rc12`，也不要将本地测试镜像名当作公共下载地址。源码部署见 [全新部署指南](../../docs/FRESH-INSTALL.md)。

## 本次交付

- 统一部署任务：MySQL、PostgreSQL、网站 HTTPS、SSH 与管理 HTTP/Nginx 联动；包含权限复核、端口及依赖预检、持久化进度、独立进度通道和失败恢复。
- 图形服务、RDP 共享盘和 MP4 渲染器自动启停；外部依赖统一预检；Agent 签名仓库、WAL/PITR 与网页入口限制专项任务。需要接入匹配的部署执行器。
- 平台配置按服务部署、外部依赖、业务策略、状态与发布分组，区分期望、配置应用、依赖就绪和实际服务。
- 项目标识、Go 模块、协议横幅、下载路径和数据根目录统一为 Puppeteer。图形客户端与 MP4 回放使用校验过摘要的 Apache Guacamole 1.6.0 官方源码。
- 明确网页内 RDP 与原生 RDP 的部署边界。网页内 RDP 使用 guacd，不需要原生 Worker，也无需开放平台的 3389/13389 端口。
- 更新中英文 README、安装升级、执行器及组件说明；新增源码版本校验脚本。安装器内置经过摘要校验的 AppArmor 策略，修复固定旧版本下载地址不存在该文件的问题，保留现有镜像默认值。

## 数据及升级

108、109 迁移增加配置预检与备份验证清理记录；110 更新生成的产品默认名称。迁移保留账号、资产、密码、自定义名称和历史校验记录，备份工具支持 schema 110。

应用数据目录为 `/var/lib/puppeteer`。匹配的升级脚本识别原运行时目录，在原位置备份，并将同一个命名数据卷挂载至新位置；不重新生成密钥。四个历史迁移文件的名称变更采用明确的原始/新摘要对应表；其他 SQL 内容修改仍被拒绝。完整说明见 [升级与恢复](../../docs/UPGRADE.md)。

Agent 新安装路径、客户端缓存身份及独立许可标识有调整；已有原生客户端需要重新登录，旧签名许可需由自己的签发者重新签发。`NT_*` 环境变量及 `nt` 命令保留兼容。许可证版权署名与 Git 历史保留。

## 边界

原生 RDP 当前交付能力识别和专用本机部署预检，不包含通用公网 Worker 自动安装。浏览器 RDP 使用独立图形组件，不受该限制影响。

自动化不修改防火墙、云安全组或 DNS。Windows Docker Desktop 本地验证不等于 Linux/systemd 整机或 AppArmor 内核强制访问验收。远程整机干净安装、既有数据升级、镜像发布及相应环境验收仍须在镜像发布前完成。现有 Linux 一键安装流程要求匹配的镜像、接管脚本和 systemd；不能把普通 Compose 启动成功当作执行器已接入。
