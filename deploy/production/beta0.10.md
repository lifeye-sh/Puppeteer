# Puppeteer beta0.10

2026-11-16，Linux amd64，数据库 schema 110、能力版本 90。本次发布恢复密钥管理与批量访问授权，沿用 beta0.9 的数据库结构和部署组件。

## 本次变更

- 首次可写启动自动生成 age 恢复密钥；已有部署未配置恢复公钥时自动补齐。已有自有公钥保持不变，重复启动不会重复生成。
- 管理员可下载恢复私钥、重新生成密钥，并下载历史密钥。私钥加密保存，下载与重新生成沿用密码/MFA 校验和审计；历史备份仍使用其原密钥恢复。
- 访问授权支持同时选择多个用户、部门、资产及分组，按人员与资源组合批量创建授权，单次最多 500 条关系。
- 批量授权支持统一有效期和适用策略，保留已有授权并跳过重复关系；无效引用或审计失败时整批回滚。数据库授权沿用数据库策略，不附加 SSH 策略。
- 安装及升级默认目标同步为 beta0.10，四个组件使用发布清单中的固定摘要。

## 验证范围

功能开发阶段已通过恢复密钥并发初始化、加密存储、权限/MFA、轮换及历史私钥下载测试；实际启动和重启验证，以及控制面/完整加密备份恢复回归通过。批量授权已通过 PostgreSQL 集成测试，覆盖双向组合、重复跳过、有效期、可见范围、混合数据库策略、并发幂等、非法引用和审计失败回滚。

两项功能已部署到本地 Docker，后端、网页健康检查、实际静态文件校验和部署执行器连接通过；实际启动生成一份有效恢复密钥。发布验证包括前端生产构建（507 个产物）、79 项前端与脚本测试、相关 Go 测试，以及最终安装升级 Python 回归（61 项：60 通过、1 项环境跳过）。四个远端镜像摘要和安装器版本一致性校验通过。

使用实际 beta0.10 镜像完成隔离 Linux/systemd 全组件新安装，以及 beta0.9 核心部署升级至 beta0.10；均验证 schema 110、服务健康、部署执行器 active、恢复密钥自动生成和新增接口注册。升级另验证业务探针数据、原有配置密钥、命名数据卷及备份校验清单保留。测试仅将配置下载指向当前源码夹具，镜像拉取、安装、备份、升级和健康检查均实际执行。

此前 beta0.9 优化的第二轮 10 小时隔离长测在本次发布准备时仍运行中，不将其列为本次通过项。它不等同于真实 Windows RDP 或独立整机验收。

## 安装与升级

镜像为 `cloners/puppeteer-{server,web,graphics,renderer}:beta0.10`，固定摘要见[发布清单](dockerhub-beta0.10.json)。图形和渲染组件没有新增功能变更，统一版本便于配套部署。

新部署使用[一键安装](../../docs/ONE-CLICK-INSTALL.md)；已有部署先预检再升级：

```sh
sudo bash upgrade-puppeteer.sh --dir /opt/puppeteer --version beta0.10 --check
sudo bash upgrade-puppeteer.sh --dir /opt/puppeteer --version beta0.10
```

无需新增端口、挂载或手工生成 age 密钥。生成恢复密钥不会自动启用定时备份。管理员应在“备份与恢复 → 备份策略”下载私钥并独立保管。更换自有公钥前，保留原私钥以恢复旧备份。

升级会备份数据库、配置和应用数据，并保留现有密钥、数据卷及组件配置；维护期间已有会话会中断。详见[升级说明](../../docs/UPGRADE.md)、[批量授权](../../docs/BATCH-AUTHORIZATION.md)和[备份恢复](../../docs/backend/implementation/backup-restore.md)。

AI Agent 全功能操作方案仍处于规划阶段，不属于此版本功能。
