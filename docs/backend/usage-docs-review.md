## 接入能力不能按协议名一概而论

下表是官方使用文档行为基线与本方案交付边界。是否可用还要同时满足实现状态、许可、用户权限、目标协议能力。

| 入口 | 文件能力 | 共享/监控/终止 | 需要独立验证的内容 |
|---|---|---|---|
| 浏览器 SSH | 目标 SFTP，目标需支持 | 共享已文档化；监控/终止按服务实现验收 | PTY 命令识别边界、chmod、断线与关闭标签语义 |
| 浏览器 RDP | 平台存储经映射盘中转 | 共享已文档化；图形监控/终止专项验收 | RemoteApp、音频/麦克风、PDU、剪贴板双向控制 |
| 浏览器 VNC | 无文件管理入口 | 共享已文档化 | 剪贴板兼容性、图形错误码、录像 |
| 浏览器 Telnet | 无文件管理入口 | 不承诺共享 | 交互登录、命令识别、字符编码 |
| 原生 SSH | 不因 SSH 登录自动承诺 SFTP subsystem | 不继承浏览器共享能力 | 交互选择、名称/别名直连、密码/公钥认证、转发白名单 |
| 原生 RDP | 客户端磁盘和剪贴板重定向，区别于平台存储 | 官方明确当前不支持 Web 在线监控和主动断开 | 票据、两段 NLA、RemoteApp、录像与实际策略执行 |
| Termark | 随实际代理能力，不能默认等同 Web | 随实际代理能力 | 设备授权与目录同步、HTTPS 隧道、前置认证、mTLS |
| 数据库客户端 | 不使用会话文件 API | M10 自有连接状态 | MySQL 协议分类/事务/预处理；PG 单独扩展 |

原生 RDP 限制来源：[RDP 代理服务器](https://www.next-terminal.com/zh/docs/usage/rdp-server.html)。新后端可以增加终止能力，但必须作为另行实现并验证的扩展；未通过前返回 `unsupported`，禁止静默成功。若某种入口无法执行当前资源要求的文件、剪贴板或撤权策略，拒绝该入口，不能仅靠生成客户端配置文件实施访问控制。

## 需要明确记录的文档差异

| 事项 | 证据差异 | 本方案决策与验证方式 |
|---|---|---|
| SSH 目标标识 | 资产文档称“别名”，SSH 代理文档称“名称”；当前前端中文提示同时提到两者 | 支持别名优先与名称兼容，冲突拒绝；不再假设必须用 asset ID；用两个同名资产验证 |
| 数据库用户编码 | 文档明确 `username@asset_name`；原规划自行设计了 `platformUser#assetId` | 修正为文档编码，解析到唯一已授权数据库资源；歧义/分隔符约束显式报错，新增编码只能另立版本 |
| OIDC URL | 正文通用表列 `/api/oauth2/*`；截图与当前 `OidcServerSetting.tsx` 为 `/api/oidc/server/*` | 当前前端路径作为主契约，Discovery 返回这一组；旧路径可做同一 handler 的版本化别名，不能建立两套独立签发状态 |
| 临时白名单续期 | 正文笼统说持续访问续期；截图及 `TempAllowView.tsx` 有 autoRenew，当前默认 false | 明确配置开关；滑动 TTL 与新增绝对期限分开，绝对期限是本方案增强 |
| SQL 查询 | 正文称 SELECT 放行，截图还显示 SHOW 元数据查询 | 普通查询和元数据查询应可用；多语句、写 CTE、SELECT INTO OUTFILE、函数副作用等不能按字符串前缀判只读；这是实现防护要求 |
| 数据库种类 | 使用文档只给 MySQL 代理流程 | 首个兼容验收以 MySQL 为准；原有 PG 规划保留为独立适配器，内部 PostgreSQL 存储不等于支持 PG 代理 |
| Agent 身份 | 文档配置为 API Key，原设计偏向节点证书 | 注册 API Key 归 M05，凭据材料由 M04 保护；自有证书升级路径属于新协议，不假定官方二进制互通 |
| 真实 IP 信任 | 官方补充文档说明固定追加私网/回环网段 | 本方案默认仅显式信任代理，提供标明差异的旧行为兼容模式；安全策略不得依赖伪造 Header |
| 原生 RDP 重定向 | 官方 .rdp 默认剪贴板与全部本机磁盘开启 | 记录兼容基线；本方案按实际策略生成并在代理端执行能力约束，不能仅改 .rdp 就称已禁用 |
| OTP 恢复码 | 文档有恢复码流程，当前 account API 未找到对应恢复码路由 | 补后端需求和前端联调项，禁止把设计写成当前 UI 已支持 |
| 备份格式 | 文档给出 .ntbak 扩展名和内容边界，未给容器/加密/版本规范 | 默认设计自有版本化归档格式；官方格式互操作需真实样本及格式契约，单独列验证门槛 |
| 证书与历史截图 | Web 文本强调 CN，截图跨多个旧版本，部分演示不匹配域名 | 服务端校验证书 SAN/主机名、有效期和私钥匹配；旧截图数值不直接当默认值 |

上述差异分别回写到模块卡、[接口文档](api-and-protocols.md)和[数据模型](data-model.md)。使用文档确认用户行为，不能凭文档推导闭源内部表结构、帧格式和实现库。

## 必须一起交付的跨模块流程

1. **原生接入**：M01 验证主体 → M02 评估授权/策略 → M06 选择入口与能力 → M03 解析目标 → M04 发出秘密租约 → M05 拨号 → M08 记录结果。票据签发和消费都校验权限，目标凭据不返回客户端。
2. **SQL 工单**：M11 固化 SQL/hash/目标 → 审批事务写执行意图和 outbox → M10 复核权限并执行 → M11 保存成功/失败/部分成功/unknown → M08 留证 → M14 通知。审批成功是自动执行的触发，不再等待无文档依据的第二次“执行”点击。
3. **mTLS Web**：M13 解析证书与吊销状态 → M09 匹配唯一入口域名 → M01 关联身份 → M02 校验资源或公开访问策略 → M05 转发 → M08 留证。TLS 证书认证不自动赋予资产权限。
4. **恢复**：M16 检查清单/版本/密钥 → M18 进入维护模式并阻止新任务 → 安全备份 → 恢复数据库和 CA → 独立恢复对象 → 重启/撤销旧票据 → 核验用户、授权、秘密解密及录屏/驱动盘。恢复任务控制状态另存于恢复过程不会覆盖的运维日志，避免恢复自身抹掉进度。
5. **CLI**：`cmd/nt` 只装配模块公开用例，在线命令使用管理员身份，离线应急命令使用明确的主机操作身份并写恢复审计；不能把 CLI 做成第二套 SQL 后门。

## 配置和 Agent 参考值

[系统属性目录](system-property-catalog.json)登记了 103 个官方键及其领域所有者。原表均声明 string，内部必须分别解析 bool、枚举、整数、时长、字节数、URL、秘密引用。官方原始单位保留在 unit；本轮依据 UI 确认 `access-mfa-expires-at` 为分钟，并在 internalUnit 和设计规范补齐内部单位。103 键均已填写 proposedDefault、validation、effect；官方未知默认值仍单独保留。兼容 property API 由 M18 承接，业务校验和应用行为归各 owner。

Agent 的文档参考配置为 `~/.nt/agent.yaml`，缺失时生成默认配置，指定路径优先；默认 endpoint `http://localhost:8080`、TLS 跳过校验 false、名称使用主机名、采集 5 秒、心跳 30 秒、自动更新 true/10m。HTTP/HTTPS 分别形成 WS/WSS；endpoint 不含 API 子路径。HTTP/SOCKS5/SOCKS5H 代理要求显式有效端口，SOCKS5H 在官方描述中按 SOCKS5 处理，不能自行承诺不同 DNS 解析语义。[官方配置说明](https://www.next-terminal.com/zh/docs/usage/agent-gateway-config.html)

网卡 include 非空优先于 exclude；默认排除回环及常见虚拟接口；无效正则的官方行为退回最低限度回环排除。磁盘按挂载点精确匹配，默认 Unix `/`、Windows `C:`；非正采集/心跳间隔回默认，无法解析的更新间隔回 10m。本方案在管理配置时额外显示校验告警，不能静默扩大采集范围。采集指标由 M15 消费，注册/版本/通道仍由 M05 管理。

## 实施方案已补齐，按任务验收

原待定技术路径已收敛为 [D01–D07 可落地实施决策](implementation-decisions.md)，不再以笼统 PoC 作为开发说明：

- Termark 采用公开 SSH URI，自有 nt-client 负责 PKCE/HTTPS 桥接；Agent 采用 WSS/yamux、专用设备凭据及 TUF 更新。
- 原生 RDP 采用 FreeRDP 侧车，明确票据回调、两段认证、通道策略、软件帧录屏和进程终止，分 profile 验收。
- 备份采用自有 `.ntbackup.age`，明确 DB/CA/KEK/对象边界、隔离恢复、回退和旧系统逐领域迁移。
- 能力使用 local 或本项目独立签名 provider；103 属性已定义内部类型、默认值、校验和生效方式。
- 官方专有 Termark/Agent/.ntbak/许可仍需外部契约和真实 fixture，不冒充已有互通；嵌入视频缺口保留在来源审计中。

上述是可开发规范，产品实现和实机测试仍按任务逐项执行。

文档校验命令：`node scripts/backend-module-docs.mjs`。它检查表归属、来源覆盖、需求主责/协作引用、属性键唯一性和依赖无环，并重建模块卡及覆盖矩阵。校验通过仅表示规划一致，不表示产品功能已通过测试。
