# 原生 MySQL 受控 DML

schema100 开发验收中；是否已部署以 R16.md 最新记录为准。

默认 `db-proxy-block-dml=true`，升级不会自动允许已有数据库写入。PostgreSQL 保持只读，审批 SQL 工单保留独立执行链路。

## 配置顺序

1. 在目标 MySQL 创建专用账号，仅授予所选数据库的 `SELECT / INSERT / UPDATE / DELETE`，要求 TLS。不要授予 `ALL`、DDL、`EXECUTE`、`FILE`、管理权限、角色或其他数据库权限。
2. 在数据库资产“凭据与 TLS”选择“原生 DML 凭据”；可在表单内新建。它必须与只读、审批执行凭据不同。测试连接验证 TLS、凭据及目标授权，不写入目标数据。
3. 给使用者分配资源授权及 `database.write`（数据库原生受控 DML 写入）权限。
4. 在“平台设置 → 数据库”关闭“阻止数据库原生 DML”，完成管理员密码及已绑定 MFA 复核，等待在线节点全部确认。
5. 客户端使用原来的平台数据库专用密码重新连接。已有只读连接不会升级。门户连接说明按当前权限提示是否允许受控 DML。

## 执行与撤销

- 新写连接使用独立目标账号，仅增加单条、经 AST 校验的 INSERT / UPDATE / DELETE。支持文本和参数化语句、事务提交/回滚；仍拒绝 DDL、CALL、文件操作、多语句、未知函数、跨库写入及不支持的语法。
- 每条协议命令及5秒租约复核用户、资源授权、资产版本、写权限、全局策略和写凭据版本。禁用/撤销后关闭连接，不自动改为另一个目标账号，不自动重试。
- SQL 审计记录受影响行数；参数仅保存类型/长度/NULL 元数据。目标确认某条语句不代表包含它的事务最终提交。无法收到目标响应时记录 `unknown`，须到目标数据库核实。
- 断开时未提交事务由目标引擎处理。MyISAM 等非事务引擎、目标触发器及外键级联可能产生不可回滚或额外副作用；该通道不承诺业务事务可回滚，也不提供批量写入预审批。需要审批和固化 SQL 时使用 SQL 工单。
- 目标数据库管理员负责目标账号权限与对象行为；平台不修改目标 GRANT。启动连接校验目标权限，目标管理员变更权限后应结束旧连接并重新测试。
- 隔离恢复重新启用全局 DML 阻止，且数据库资产仍按恢复隔离策略停用。

## 验证

`TestR16NativeDatabaseDML` 在独立 MySQL8.4 夹具测试两节点 ACK、默认阻止、无角色只读、已有连接不升级、文本/绑定写入、commit/rollback、角色撤销/全局禁用时回滚、凭据轮换、门户脱敏、审计参数保护和恢复默认。

`TestR16DatabaseDMLConfigurationMFA` 验证缺少及重放 MFA 拒绝。`TestDMLAffectedRowsAndLostAcknowledgement` 验证受影响行数和丢失响应的未知结果。执行结果以对应日志为准，不替代完整 R16 验收。
