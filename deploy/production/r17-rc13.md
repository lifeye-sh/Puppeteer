# Puppeteer r17-rc13

日期：2026-11-15。Linux amd64；schema 110，能力版本 90。

本版本承接 [rc12 源码交付](r17-rc12.md)，发布配套 server、web、graphics 和 renderer 镜像，以及匹配的一键安装与升级流程。四个远端摘要均已核验，构建源码提交与摘要见[镜像清单](dockerhub-r17-rc13.json)。rc12 源码标签保留，不改写历史标签。

网页内 RDP 使用 guacd，不需要原生 RDP Worker。Linux 一键安装完成后自动接入部署执行器；现有安装升级保留数据卷、密钥与组件停用状态。升级需要维护窗口，先备份配置、数据库和应用文件。脚本不修改防火墙或云安全组。

升级跨越 schema 110 后不能直接切回 rc11 镜像。发生失败时保留备份和诊断文件，按升级说明恢复。

## 验证与边界

- 46 项安装、升级及接管脚本回归，包括官方组件镜像更新、停用状态与自定义镜像保留。
- 13 项前端发布与 HTTP/代理测试，发布清单和安装器默认值一致性检查；503 个前端发布文件校验。
- 发布 renderer 镜像内完成 3 项录屏测试，包含真实终端、图形 H.264 编码与原生录像时间线。
- 发布 server/web 镜像在真实 systemd 管理的隔离环境完成执行器接管、管理入口联动和 API 停止期间的独立进度访问。
- 完整组件全新安装：PostgreSQL、server、web、guacd、MP4 健康，schema 110，执行器自动安装并处于 active 状态。
- 真实 rc11 核心部署升级至 rc13：预检保持原 schema 107，升级后 schema 110；数据库标记记录、原密钥摘要及命名数据卷身份保持不变，升级备份生成，服务健康且执行器自动接管成功。

上述部署验收运行于 Windows Docker Desktop 的隔离 Linux/systemd 环境。测试配置下载使用相同提交的本地文件，镜像从真实仓库按摘要拉取；Docker、证书生成、数据迁移、备份及服务管理实际执行。应用容器不挂 Docker socket，测试宿主用于控制隔离项目。未对用户远程服务器执行升级，未完成启用 AppArmor 的实体 Linux 宿主内核强制访问验收。原生 RDP 通用 Worker 自动部署仍不在本次交付范围。
