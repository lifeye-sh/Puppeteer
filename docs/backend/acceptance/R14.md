### 已实现

- 迁移 049：内置公共客户端 `nt-native-v1`，无内置客户端密钥；独立 `nativeEnabled` 管理开关，默认关闭，不要求启用第三方 OIDC 服务。
- 复用授权码与 S256 PKCE，显式网页同意；回调仅允许 `http://127.0.0.1:{1024..65535}/callback`，端口外任何部分不可变。交换授权码时必须精确匹配原端口及 verifier；错误 verifier 会消费授权码，不能重试复用。
- 原生 scope：`assets:read`、`sessions:connect`、可选 `offline_access`；不授予 OIDC 用户声明或客户端凭据模式。access 5 分钟；refresh family 7 天，逐次轮换，重放撤销整族。原生令牌不能当网页登录态、个人 API Key 或第三方 OIDC 令牌使用。
- `GET /api/native/v1/assets?limit=100&cursor=`：每页重验用户、令牌、scope 和当前资产授权；只返回 id/name/alias/protocol/revision/entries，不暴露主机地址、目标凭据和网关秘密。目前 `entries=[]`，不会暗示连接能力已完成。
- `nt-client assets`：Windows/Linux/macOS 的 Go CLI，通过系统浏览器和随机回环监听完成授权，校验 state，读取目录后注销该次令牌。仅支持 HTTPS，使用系统信任链及可选 PEM CA，拒绝重定向，限制响应大小及分页次数。令牌只存内存，每次运行重新登录，不写明文凭据文件。
- 管理界面：OIDC 应用客户端 → 服务端设置 → “允许自有原生客户端登录（PKCE）”。该开关受 capability gate 控制。个人中心可撤销内置客户端的应用授权。
- 外部身份提供方跳转期间保留同标签页安全回跳地址，5 分钟有效、一次性读取；仅允许本平台授权路径，不接受外部 URL 或带用户密码的 URL。
- 隔离恢复关闭原生客户端入口并撤销授权；重新启用需管理员密码复核。

### 使用方法

管理员在 OIDC 服务端设置保留固定 HTTPS Issuer，启用原生客户端开关；无需打开第三方 OIDC 开关。当前开发二进制构建到 `backend/.local/nt-client-windows-amd64.exe`（另有 Linux amd64 与 macOS arm64）。

```powershell
.\backend\.local\nt-client-windows-amd64.exe assets --server https://backend.localhost:5174
```

可加 `--no-browser` 手动打开输出的授权链接；私有 CA 使用 `--ca <PEM文件>`。不要传平台密码或目标密码。浏览器完成平台登录、必要的验证码/MFA后，点击“允许授权”，CLI 输出已授权资产目录后自动注销。需要实际连接时暂继续使用现有网页终端。

### 已实现的边界

- `POST /api/native/v1/connect`：`sessions:connect` 原生 access token、资产授权和策略校验；请求包含 `assetId/entry=ssh/clientVersion/idempotencyKey/clientPublicKey`。同一用户的幂等重试仅返回原会话状态，不重发票据；改变资产、只读设置或临时公钥会拒绝。
- 60 秒一次性桥接票据使用 32 字节随机数及带用途前缀的 HMAC 摘要，绑定会话、用户、授权族及来源 IP。`GET /api/native/v1/bridge` 仅接受 Authorization Bearer 与 `nt-bridge.v1`；禁止 URL 票据、浏览器 Origin/cookie 混用、压缩及文本流。
- WSS 内终止 SSH 协议，再由平台凭据库建立目标 SSH 连接；没有把目标原始 TCP 交给客户端。双向校验本次预留绑定的临时 SSH 公钥，票据本身不足以使用连接；服务端临时私钥加密保存，消费后立即清除，未消费的过期密钥由维护任务清理。
- 单个 shell 或 exec 通道，支持 PTY 与窗口尺寸变化，保留目标退出码；SFTP、Agent 转发、TCP 转发、额外 session、环境变量和其他请求明确拒绝。复用现有 Agent/SSH 跳板/网关组/代理拨号实现，但本批实机验证的是直连 SSH fixture，不把各网关组合记为已验收。
- 复用在线会话、资产/凭据/主机密钥版本检查、命令策略、输入识别审计和录屏。每 2 秒验证授权族、同意、用户、客户端、服务开关、auth epoch 及资源授权；租约 10 秒，原有 4 小时上限仍生效。已连接会话不因 access 的 5 分钟期限提前断开，新连接仍必须使用有效 access。
- `DELETE /api/native/v1/sessions/{id}`：原生令牌持有人仅能终止自己的会话，重复调用幂等；管理员仍可通过现有在线会话管理终止。审计写入失败时停止传输。
- WSS 消息上限 64 KiB，应用输入/录屏分块 16 KiB，双方写阻塞上限 15 秒，SSH 建立阶段有超时。断开会关闭整个连接，不承诺 TCP 半关闭。
- 修复新增路径中的独立嵌套事务自锁：命令审计与授权、已连接状态使用同一事务，且在目标开始执行前落库。现有浏览器终端路径继续通过回归。

### 2026-11-10 客户端磁盘重定向(策略与逐操作闸门)

- 契约：`nativeRDPTarget` 增加 `drives`/`driveUpload`/`driveDownload` 与四个限额字段。启用条件=平台 `RDPDriveEnabled` 且用户通道策略存在任一方向；upload（目标读用户盘）=policy.Upload 且非 readonly，download（目标写用户盘）=policy.Download；限额：单 IRP 1 MiB（files.MaxChunk），会话每方向累计 256 MiB。worker 对同一组数值重复校验，drives 与方向、限额不一致的载荷拒绝。
- 机制：worker 启动期固定 `Intercept=rdpdr`——通道模式判定（front PostConnect）早于票据消费，与剪贴板 Passthrough 的处理相同；FreeRDP 代理自带的 rdpdr 客户端/服务器状态机独立完成与目标及 mstsc 的协商。新增 `rdpdr-policy.patch`（按 pin 版 3.32.2 生成）在三个转交点接闸门：ChannelCreate 闸门仅当 profile 启用时把 rdpdr 放入目标侧通道清单；用户→目标队列在转发前过滤设备公告（仅 FILESYSTEM 设备保留，打印机/串口/并口/智能卡/未知类型移除）；目标→用户 running 态逐 PDU 走 IRP 闸门。闸桥钩子以弱声明接入修复后 SDK，worker 二进制提供强符号，无 worker 时代理行为保持原样。
- 逐操作限制：IRP_MJ_READ 请求按 upload 策略与单 IRP+累计配额放行并按 CompletionId 登记；完成应答以实际回传字节入账，超过请求长度或与 PDU 长度矛盾即视为违规；IRP_MJ_WRITE 的负载在请求 PDU 内，按 download 策略即时入账。任一方向首次溢出记录 OVERFLOW 事件并 fail-closed（后续请求一律拒绝），未启用方向记 DENIED。CREATE/查询/关闭等元数据 IRP 放行，CREATE 的 UTF-16 路径转 UTF-8 后进入审计。
