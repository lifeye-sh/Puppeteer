# R16 统计、登录控制与运维告警

本手册覆盖 `r16-operations-preview` 的已实现切片，不代表 R16 全部验收。完整余项仍见 [R16](R16.md)。

## 前端操作

- 首页趋势来自保留期内的完整主机会话记录；资产环图使用真实协议及目录授权。数据库和 Web 访问不混入主机会话统计。
- “会话审计 → 访问统计”：选择日期（最多366天）、本人/全部范围，查看按日次数、用户、资产、失败会话和实际连接操作时长，下载CSV。按浏览器时区汇总，空日期补零；整体独立用户数不按天相加。
- “平台设置 → 运行配置与版本”：品牌文字、登录会话、登录失败锁定、PostgreSQL四个标签页。新配置仍需等待节点ACK。
- “身份认证 → 登录锁定”：区分账户与来源IP，管理员可解锁。
- “系统运维 → 监控与告警 → 告警与系统事件”：新建、修改、禁用、删除规则；查看、确认事件。确认仅标记已查看，不解除告警。
- “监控与告警 → 平台指标”：后端进程/操作系统命名空间、数据库连接池、全局有效会话和存储账本；Agent指标单独展示。连接池累计值在进程重启后重置。CPU采用100ms采样，失败值保持未知。逻辑录屏大小不含MP4/外部备份，配额总和不等于磁盘容量。
- “链路诊断 → 网络与来源IP”：搜索已保存资产，选择TCP或ICMP及1..10次。TCP沿资产网关/跳板/代理路径；ICMP只支持直连。每次3秒、间隔1秒、总计最多40秒；每节点共享4个探测名额，另有用户限流。停止、离开页面或资产版本/授权改变后取消。开始与结束写入操作日志。

ICMP使用 [Go x/net非特权ICMP接口](https://pkg.go.dev/golang.org/x/net@v0.62.0/icmp)，不调用外部ping程序、不开放raw socket。Linux需运行用户属于允许的`net.ipv4.ping_group_range`；不支持时明确显示环境不支持并提供TCP替代，不会自动扩大容器权限。目标一次解析后固定IP，拒绝未指定/多播/链路本地/广播地址。来源诊断显示可信代理算法的真实选择结果，不回显完整代理头或查询外部公网服务。

## 登录控制边界

`login-lock-enabled=false` 暂停账户/IP锁定检查与失败计数，但不删除已有记录；重新启用后未到期锁定继续有效。单独时长0仅停止产生新锁定，既有锁定保持。验证码、请求限流、MFA尝试上限不受此开关影响。

来源IP锁定默认0（关闭）。启用前先确认平台识别到真实客户端来源地址，尤其是共享反向代理/NAT。仅本地密码、LDAP密码失败计入IP失败次数；其他身份服务保留其现有认证保护。成功登录不清空共享IP计数，避免一个用户成功登录抹除其他用户触发的失败记录。IP统计沿用失败窗口/阈值，到期重置；IPv4映射IPv6统一为同一地址。未经可信代理配置的XFF不被采用。

`login-session-browser-close-logout=true` 使之后签发的Cookie不含持久化MaxAge；服务端绝对到期时间保持原登录时长。已有Cookie不改写，浏览器的恢复会话功能可能保留会话Cookie，因此不能保证关闭窗口立即退出。

## 告警与通知

每10秒评估一次。支持CPU、内存、最高磁盘使用率、Agent采集静默时间、配置未应用时间。前三种资源使用率来自Agent所在操作系统命名空间，容器内数据不等于容器配额。

使用率阈值上限100%；静默/配置时长阈值15..86400秒；恢复阈值必须低于触发阈值；持续时间0..3600秒。Agent超过三个采集周期未更新则资源使用率为未知，不能据此恢复旧告警。可另建采集静默规则监控失联。

状态与事件、通知入队在同一事务提交，多节点使用事务锁避免重复触发；通知投递仍是可重试的至少一次模式，不能保证外部渠道绝不重复。规则修改/删除取消旧条件并保留历史事件，不把人为取消冒充真实恢复。最多500条未删除规则。

通知配置中勾选“运维告警触发”“运维告警恢复”，接收人类型必须为“指定人员”；投递前重新检查接收人启用状态及 `identity.manage` 权限。还需启用渠道、人员绑定和通知偏好。静默时段、失败重试沿用现有通知服务。通知只含规则名称和事件ID，不含凭据、命令或文件内容。

## CLI

在受控服务器环境中使用同版 `nt`，读取部署环境 `NT_DATABASE_URL` 与运行profile。命令不执行数据库迁移；schema不匹配直接拒绝。配置仅包含当前注册表的非秘密键。

```text
nt settings schema
nt settings show
nt settings check --revision CURRENT --operator EXISTING_ADMIN --reason "review configuration change"
nt settings apply --revision CURRENT --operator EXISTING_ADMIN --reason "approved configuration change"
```

check/apply 从标准输入读取例如 `{"set":{"system-name":"内网运维"}}`。check 在事务内执行真实校验后回滚，不改变当前修订；数据库序列允许产生空号。apply 要求当前修订匹配并写入操作审计，之后通过show检查节点ACK，不能把“写入成功”当作“已应用”。operator用于本机特权操作的审计归属，必须是现有启用管理员，不是远端登录认证。

## API与数据所有权

| 接口 | 权限与行为 |
|---|---|
| GET `/api/statistics/sessions` | 已登录；默认本人，all=true需session.read；from/to日期、timezone IANA时区、format=csv |
| GET `/api/statistics/assets` | 已登录；默认已授权且启用资产，all=true需asset.read；协议计数沿用目录授权规则 |
| GET/POST `/api/admin/monitor-rules` | identity.manage；列表/创建 |
| PUT/DELETE `/api/admin/monitor-rules/{id}` | identity.manage；修改JSON版本号，删除version查询参数；旧版本409 |
| GET `/api/admin/system-events` | identity.manage；100条，before时间及beforeId组成稳定游标 |
| POST `/api/admin/system-events/{id}/acknowledge` | identity.manage；幂等确认、操作审计 |

M15 `internal/modules/operations` 拥有monitor_rules和system_events；M18拥有配置修订；M14拥有通知队列。会话与资产统计分别复用M06/M03读取规则。schema69后系统事件可单独配置保留策略，升级默认永久保留，管理员预览并保存有限期限后才自动清理。

## 部署与回退

### 分类日志保留（schema69）

平台设置中的“审计日志保留与保全”按访问、登录、任务、SQL、管理操作、文件操作、系统事件分别配置。访问保持现有31天（或升级前管理员已配置值），其余类别为永久保留，避免升级自动删除历史。数值只接受-1或1..3650。缩短前先点“预览清理影响”，核对可清理数和超期保全数，再保存；预览绑定管理员、当前版本、键和值，十分钟过期。任何期间的配置修改都会要求重新预览。

清理每分钟执行一批，每类最多25条、整批事务提交；失败回滚。访问以closed_at、SQL以finished_at、文件以ended_at、任务以jobs.ended_at、登录/操作/事件以created_at计算；运行中操作不清理。访问清理包含录屏、命令与关联导出取消，独立文件/SQL日志各有自己的策略。定时任务仅清除输出与快照，保留schedule/trigger去重标识并从历史查询隐藏，避免重启重复执行。

“保全记录”需要管理员、合法类别和现存记录ID，新增和解除都必须填写原因并审计。与清理共用数据库事务锁；已清理记录不能补设保全。保全不会因缩短期限失效。解除后超期数据可能在下一批删除，调长期限不能恢复已删除数据；如需恢复，使用R11隔离恢复流程。

CLI与网页使用同一预览验证。向以下命令输入相同JSON，例如`{"set":{"access-log-saved-limit-days":31}}`：

```text
nt settings retention-preview --revision CURRENT --operator EXISTING_ADMIN --reason "review retention impact"
nt settings check --revision CURRENT --operator EXISTING_ADMIN --reason "validate retention policy"
nt settings apply --revision CURRENT --operator EXISTING_ADMIN --reason "apply reviewed retention policy"
```

preview仅记录十分钟审查凭据和操作日志，不改变保留策略；check回滚；apply提交后查看show的节点ACK。CLI已修正无变化时错误沿用历史changedKeys的问题：没有变化返回空数组，apply标为unchanged，不产生新配置版本。

schema69部署前备份`backend/.local/pre-r16-069.dump`，273279115字节，源/副本SHA256为`9333d80485c4761ad01cb2495dd57ff565585c58beed4d446da3cfc44bcbd0fd`。旧schema68二进制不能读取扩展后的完整快照；不得直接替换旧二进制声称无损回退。

新增schema64：布尔登录控制、IP锁定表、会话Cookie快照；schema65：告警规则与系统事件；schema66：品牌文字。旧的只支持整数快照的服务不能直接读取这些配置，不能简单换回旧二进制。

部署前备份 `backend/.local/pre-r16-066.dump`：273260209字节，SHA256 `033fa21d2526e9debc3ba497c736fa882572a4a4cc90d85907e1f45d63d13151`。备份源和本地副本一致。必要时按R11隔离恢复流程验证备份；不要覆盖有新写入的业务库来冒充无损回退。


### 平台设置入口（revision46）

进入 /system-status，左侧选择品牌、登录安全、数据库参数、日志保留、许可配额、配置发布或运行状态。各分区可由 ?section=branding|login|postgres|retention|license|publish|runtime 直接打开。编辑弹窗只提交当前分组；版本冲突保留填写内容，取消并刷新后重新编辑。日志缩短仍需预览。

配置发布默认仅显示在线节点，开启“显示已停止节点”可查看旧节点。历史列表用“差异”对照上一版或当前版；“快照”展示只读值。回到旧配置需将目标值重新输入并保存为新版本，不能直接覆盖历史。页面过滤失联节点只影响展示，不改变应用状态判断。


## 配置发布节点排查（r16-config-nodes）

进入“平台设置 → 配置发布”。“目标版本”是当前已提交快照；“最近成功版本”是节点最近有效确认记录，不能据此推断既有会话已切换参数。正常心跳不增加应用轮次；首次应用、失败后的显式重试、已生效后的复检失败会记录轮次。

1. 点击“刷新状态”检查在线待确认数量。已生效只代表当前在线节点确认；离线数包含已停止的旧部署实例。
2. 开启“显示离线节点”，核对节点标识、最后心跳和版本。失联和主动停止均显示离线，需要结合容器/服务状态判断，页面不会擅自删除记录。
3. 有失败记录时，管理员可点击“重试失败节点”。只重置当前版本失败记录，成功节点不重置；离线节点恢复后才执行准备。页面重试不等于重新启动服务。
4. 如果版本已变化，刷新后核对新版本再操作。不能重试历史版本来覆盖当前快照；需要恢复参数时编辑并提交新版本。
5. 配置准备失败会暂停相关新连接，既有会话按其原快照运行；节点恢复后重新读取当前数据库配置。当前机制不提供监听器无中断热切换，不能把本矩阵当作真实跨主机网络分区验收。


### schema73 运维工具兼容

`r16-config-ops` 修复配置 CLI 的旧版本硬编码，并完成 schema73 备份恢复验证。`nt settings show/check/apply` 要求数据库版本与该 CLI 内置迁移版本完全一致；不匹配时应部署对应版本工具，不能修改数据库版本号绕过检查。备份兼容上限由显式常量和迁移一致性测试约束，未来升级需要再次验证恢复。恢复只操作隔离库，恢复后的源配置节点均显示离线，历史确认记录保留。

### 默认 LDAP 目录（schema87）

进入平台设置的“LDAP目录”，先填写地址、Base DN、服务DN、可信CA与密码，确认稳定身份属性；平台会创建独立的默认目录ID。已有目录不自动迁移。地址/Base DN/稳定身份属性创建后锁定，更换身份域请在LDAP目录管理新建独立目录。

登录与个人绑定分别默认关闭；开启等待配置发布节点确认，关闭立即生效。每次编辑需要管理员密码和已绑定的动态口令。若此目录是关闭本地密码登录后的唯一已验证管理员途径，先重新开启本地密码登录或验证另一管理员途径，再修改目录，避免版本变化使唯一登录凭据失效。

目录管理中可检测服务连接、验证用户密码、预览完整目录和分批导入；默认目录的配置按钮指向平台设置。同步总量上限1–10000，单次应用最多100人；超限整体失败，不应用截断目录进行离职停用。邮箱只是未验证的目录声明，不作为账号合并或找回依据。

`nt settings schema/show`可检查配置；通用check/apply拒绝LDAP写入，应使用带密码/MFA复核的设置API。隔离恢复关闭登录与绑定并保留加密历史。升级后旧schema85二进制不能读取新增配置快照，不应直接替换旧程序作为无损回退。

### 会话空闲超时（schema88）

平台设置“远程会话”（`?section=access`）配置access-max-idle-second，默认900秒；-1不限，1–86400为秒数，0无效。缩短立即约束后续输入和租约检查，放宽等待在线节点确认。以服务器记录的授权输入为准，输出、浏览器心跳、窗口尺寸变化和观察者流量不延长。

适用于网页SSH/Telnet/RDP/VNC、原生SSH和客户端转发。原生RDP目前只读，无客户端输入活动；独立文件管理和数据库连接不受这个键控制。超时关闭记录idle_timeout；失效连接不能通过迟到输入恢复，需要重新创建会话。配置读取失败拒绝继续输入，活动时间目前逐请求落库，没有采样或浏览器时间信任。

### Passkey配置（schema89）

平台设置“Passkey”（`?section=passkey`）编辑允许开关、RP ID和HTTPS来源；来源每行一个。兼容允许开关默认为true，但必须有合法RP配置才能注册或登录。RP空且来源空继承部署中的NT_PASSKEY_RP_ID和NT_PASSKEY_ORIGINS；来源还必须在NT_ALLOWED_ORIGINS中。不能把开关true误认为未配置时也能登录。

每次实际修改要求管理员密码与新鲜的已绑定TOTP，删除所有未完成挑战；原值保存不删除。关闭立即生效，重新开启等待节点确认，之前的挑战仍不可用。更换RP会使旧RP凭据无法用于新RP，旧凭据保留；现有已登录会话不因关闭而退出。当前RP个人凭据仍可查看和撤销。

若已关闭密码登录且Passkey是当前管理员唯一经过验证的备用途径，禁用或更换RP会被拒绝。先恢复密码登录或验证其他途径，再修改。通用CLI拒绝修改这些键；隔离恢复禁用Passkey并撤销凭据。物理Windows Hello/安全密钥验收按用户要求跳过，不能以模拟签名测试声称设备实测通过。


### OAuth时长（schema90）

平台设置“OAuth时长”（`?section=oauthLifetime`）分别设置授权码30–300秒、访问令牌60–3600秒、ID Token 60–3600秒、刷新令牌家族3600–2592000秒。默认60、300、300、2592000，保持此前第三方客户端的30天刷新家族期限。每次修改需管理员密码及已绑定TOTP；此页面不改变第三方与原生登录开关。

修改仅用于之后签发的结果，已有授权码和令牌保持原到期时间。刷新轮换仍受旧家族绝对截止时间约束，不无限延长。原生客户端额外上限：授权码60秒、访问/ID令牌300秒、刷新家族7天；全局配置可以缩短这些上限。访问令牌有效期不会越过家族到期，expires_in返回本次实际时长。

ID Token最多3600秒，密钥轮换后的旧公钥保留3660秒以覆盖已签发令牌和短暂并发。退出或撤销仍使用独立的服务端授权检查；离线验证的ID Token在自身有效期内不能依赖服务端立即撤销。


### 平台默认OIDC与企业微信（schema91）

平台设置提供“OIDC身份源”和“企业微信身份源”，编辑按“连接与范围 / 登录与密钥”分页。配置一个默认提供方，不迁移或覆盖既有独立提供方；Issuer已经存在时应继续使用原提供方，不能重复创建。连接检测与真实授权验证在“身份认证 → 登录与身份源 → OIDC / 企业微信”操作，受管项的编辑链接返回平台设置。

Issuer/企业微信API地址以及企业微信Corp ID一经创建不可修改；换身份域需新建独立提供方。OIDC客户端ID变化要求重新输入密钥或明确清除，不能将旧密钥发送给新客户端。来源与回调使用精确HTTPS地址，发起登录/绑定时必须匹配当前平台Origin和回调路径。内网验收使用受信任的测试CA；没有跳过TLS验证选项。

登录和绑定分开开关且初始关闭，所有写入需密码与已绑定MFA。关闭立即生效，开启待在线节点ACK。任何实际提供方配置修改都会使该源的旧登录会话失效；只保存相同值不改版本。若其为唯一管理员备用登录方式，先恢复密码登录或验证另一途径，再更改。

平台不会按邮箱自动创建、合并或启用用户；目前只有预先创建并完成外部身份绑定的用户可以登录。部门默认归属仍是独立待开发项，不能把本批配置交付解释成自动开户交付。旧独立提供方可编辑scope；缺省openid，省略编辑字段时保留原范围。
