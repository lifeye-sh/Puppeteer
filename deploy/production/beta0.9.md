# Puppeteer beta0.9

2026-11-16，Linux amd64，数据库 schema 110、能力版本 90。此版本以当前优化代码发布为 **Beta 测试版**；沿用既有数据库结构。

## 本次变更

- 集成已有 P0–P2 部署自动化与独立项目标识；提供轻量、标准、性能资源档位及部署预检。未选择档位的已有部署保留原资源设置。
- 增加数据库连接池预算、后台轮询退避、重任务并发限制，以及 MP4 渲染器按需启动和空闲停止。
- 录屏转换和归档使用流式处理；转换前检查内存与临时磁盘，资源不足时排队重试；增加导出质量选项。
- 网页 RDP/VNC 增加画质档位、连接阶段诊断和协议编码复用；文件编辑器按需加载。
- 修复最后一次 sync 后完整绘图指令未进入末帧的问题；保留截断数据校验。
- 修复取消转换时浏览器关闭任务未等待完成的问题，并使用 tini 回收 Chromium 孤儿进程。
- 修复长测夹具保留已关闭连接的问题，增加资源趋势和持续僵尸进程检测。
- 版本维护、安装及升级脚本支持 betaMAJOR.MINOR，继续支持历史 r17-rcN 标签。

## 验证范围与限制

发布前已完成前端生产构建（507 个产物）、76 项前端与脚本测试、61 项安装升级等 Python 回归（60 通过、1 项环境跳过）、相关 Go/数据库集成回归、实际 Beta 镜像的 14 项渲染测试和渲染容量故障恢复检查。取消转换回归结束时无残留僵尸进程，未通过放宽 PID 限制掩盖问题。

已使用公开固定摘要镜像完成隔离 Linux/systemd 全组件新安装，以及 r17-rc13 核心部署升级到 beta0.9。两种场景服务健康、schema 110、部署执行器 active；升级验证业务探针数据、密钥和命名数据卷保留，并生成备份校验清单。配置下载使用当前源码夹具，Docker 镜像拉取、备份、服务启动及健康检查均为实际执行。

第一轮 10 小时隔离混合测试完成 600 轮会话、1200 次 MP4 下载和 10 次加密备份，没有 OOM、容器重启或不健康事件，但资源趋势复核发现测试夹具连接保留及需进一步核验的进程清理问题。修复后的短测通过。

**第二轮 10 小时复测在发布准备时仍运行中，预计北京时间 2026-11-16 21:24 后结束，尚未宣告通过。**测试为合计 2 核 / 4 GiB 的隔离容器环境与 SSH/VNC 夹具，不等同于独立整机验收或真实 Windows RDP 长测。资源峰值和泄漏结论以最终复核为准。详见[优化记录](../../docs/RESOURCE-OPTIMIZATION.md)。

## 安装与升级

四个组件以 `cloners/puppeteer-{server,web,graphics,renderer}:beta0.9` 发布；实际拉取使用[发布清单](dockerhub-beta0.9.json)内固定摘要。

新部署按[一键安装](../../docs/ONE-CLICK-INSTALL.md)操作；已有部署按[升级说明](../../docs/UPGRADE.md)先执行 `--check`，再执行升级。升级会备份数据库、应用数据及配置，保留密钥、数据卷、停用组件状态与已有资源档位，并同步部署执行器。安排维护窗口，升级期间已有会话会中断。不得通过降低数据库 schema 的方式回退。

```sh
sudo bash upgrade-puppeteer.sh --dir /opt/puppeteer --version beta0.9 --check
sudo bash upgrade-puppeteer.sh --dir /opt/puppeteer --version beta0.9
```

网页内 RDP 使用图形服务，无需安装原生 RDP Worker。当前发布不改变远程服务器的现有运行部署，须在目标服务器执行升级。
