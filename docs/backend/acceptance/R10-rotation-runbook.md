# R10 凭据轮换验收

2026-10-29。版本 `r10.3-preview`，schema 28，capabilities revision 15。

R10 规划中的命令片段、SSH 任务和凭据轮换已实现。本文记录内网开发验收；用户验收仍待确认，不代表 M04 所有未来扩展或 R11 已完成。

## 可以直接测试

- `http://backend.localhost:5174/credential-rotation`：选择 SSH 资产，新建密码或密钥轮换，查看逐目标状态、取消、仅核对认证。
- `http://backend.localhost:5174/scheduled-task`：新建任务，类型选“凭据轮换策略”；配置 cron、IANA 时区、启停、漏跑策略，预览未来 10 次时间，也可立即运行。运行结果提供轮换详情链接。
- 保留两台独立内网资产“R10 轮换验收 密码”“R10 轮换验收 SSH 密钥”，可以再次轮换或通过终端验证登录。
- 定时验收策略“R10 内网轮换策略验收”已停用，避免持续修改测试账户。手动运行仍可使用。

现有片段和 SSH 任务验收分别见 `R10-snippets-runbook.md`、`R10-tasks-runbook.md`。

## 实现与权限

1. M04 管理 `rotation_runs`、`rotation_targets`、加密候选及秘密访问审计；M12 复用 `schedules` 存储轮换策略，以 `credential.rotate` 注册任务处理器，不再维护另一套 cron 引擎。
2. F00 提供持久化 job、租约、取消、幂等和核对状态更新。定时执行与轮换共用一个 job ID；任务历史和轮换详情引用同一次执行。
3. 手动轮换需要 `credential.rotate` 和当前资产接入授权；策略管理还需要 `task.manage`。执行前重新检查主体启用状态、权限、资产/凭据版本、SSH 主机指纹和访问策略。交互核对使用当前请求来源 IP；激活前再次确认主机信任版本未改变。
4. 创建请求携带 UUID `key`；同一操作者重复请求只返回原 run。数据库唯一索引禁止同一已信任主机身份和用户名同时轮换；`unknown` 仍占用账户锁。
5. 候选密码/私钥按 target ID 绑定 AAD 加密，普通 API 不返回明文或密文。密码通过固定 `chpasswd` 命令的标准输入发送，不进入命令参数或输出日志。
6. 验证成功后创建独立的新平台凭据，并在同一数据库事务中更新该资产引用、目标成功状态和审计。原共享凭据及历史版本保留，不全局覆盖其他资产的引用。
7. 密钥先在标准 `~/.ssh/authorized_keys` 中加入候选公钥，保留旧公钥的限制选项；独立连接验证候选后才移除旧公钥。使用合作锁目录、内容比较及 SFTP POSIX 原子替换，保留无关条目，拒绝重复旧 key、候选限制被改变、符号链接和不安全权限。
8. 工作进程或租约丢失后，未发送目标取消，已发送目标变为 `unknown`，不重新入队。自动策略遇到未知结果会停用。取消/超时不能被当作远端回滚。
9. “仅核对认证”只建立新旧凭据的独立 SSH 连接，不再发送密码修改或 SFTP 写入。仅候选成功且旧凭据明确认证失败时激活；仅旧凭据成功时判为失败；两者可用、两者不可用或网络不明均保留 `unknown`。

## 使用边界与故障处理

- 当前远端适配器为 Linux SSH，密码需要 root 或免交互 `sudo chpasswd`；密钥需要 SFTP、标准 authorized_keys 和 POSIX rename。Windows/RDP 账户密码、非标准公钥路径不在本轮执行适配范围。
- 轮换改变远端账户本身，其他使用同一远端账户的客户端也必须更新凭据。保留平台旧共享凭据不等于保留该目标旧密码的有效性。
- 不支持与外部管理员并发修改同一 authorized_keys 文件；轮换期间需遵守远端锁。中断遗留 `.next-terminal-rotation.lock` 时先核对真实密钥状态，再通过现有 SFTP 清理锁，不能直接重做未知操作。
- 新旧 key 都能登录时，核对不会擅自删除任何远端 key。先通过受控运维确认并清理旧 key，再点“仅核对认证”。
- 资产、绑定或凭据版本被外部编辑后，核对拒绝覆盖新配置，应先人工确认配置和远端账户状态。
- 真实服务器的认证限流可能暂时阻止旧凭据拒绝验证，此时保留 unknown，待限制解除后核对。仅测试容器关闭了 OpenSSH source penalties，以隔离故意失败的负向测试；业务 SSH 服务配置没有更改。
- fixture 容器中验收账户保留用于前端测试；重建容器会清除这些账户，需要重新配置专用测试数据。正式业务无需部署该 fixture。

## API 摘要

| 方法与地址 | 语义 |
| --- | --- |
| `POST /api/rotation-runs` | `{key, assetIds}`，最多 20 台，201 返回 `{id}` |
| `GET /api/rotation-runs?page=1` | 自己的运行记录；管理员可查全部，每页 30 条 |
| `GET /api/rotation-runs/{id}` | 逐目标状态、原因、验证后产生的新凭据 ID |
| `POST /api/rotation-runs/{id}/cancel` | 请求取消，204 |
| `POST /api/rotation-runs/{id}/targets/{target}/reconcile` | 仅认证核对，200 返回状态；运行中或非 unknown 目标返回 409 |
| `POST/PUT /api/tasks[/{id}]` | kind=`credential.rotate` 的轮换策略；固定每目标 60 秒，忽略自定义命令 |

无权限返回 403，非法输入 422，重叠账户锁/版本冲突返回 409。失败原因采用固定原因码，不把 SSH 错误或秘密直接返回前端。
